# run-workbench Specification

## Purpose
一次运行独占一份工作目录的契约：隔离不可共享、后端由平台判定、生命周期绑定该次运行、产物有明确晋升出口、每回合改了什么可被归属到那一次运行。

## Requirements

### Requirement: 每次运行独占一份工作台

一次运行 SHALL 拥有且仅拥有一份工作台（工作目录）。同一时刻 MUST NOT 有两个运行使用同一份工作台。

工作台 SHALL 在认领落库之后、该次运行可能产生任何副作用之前创建。创建失败时该次运行 MUST 以明确失败收口并点名「工作台未建立」，MUST NOT 在无工作台的情况下继续执行——共用一个遗留目录的运行，与「跑在了别人的桌上」在事后不可区分。

#### Scenario: 两次运行各占一份

- **WHEN** 同一岗位的两份运行同时开始
- **THEN** 两者各自拥有一份不同的工作台
- **AND** 二者写同名文件时互不覆盖

#### Scenario: 工作台建不起来就以失败收口

- **WHEN** 创建工作台失败（磁盘满、路径不可写、git 拒绝）
- **THEN** 该次运行以明确失败结束，错误点名「工作台未建立」与原因
- **AND** MUST NOT 退回到与任何其他运行共用目录继续执行

### Requirement: 工作台后端由平台判定，不由使用者选择

平台 SHALL 根据目标目录是否位于 git 仓库内自动选择后端：在仓库内 → `git worktree`（隔离执行 + 分支或 commit 即产物）；不在 → 普通目录。

使用者 MUST NOT 需要回答「这次算代码还是日常事务」。两后端对使用者的契约 SHALL 相同：独占、有生命周期、有晋升出口。

工作台 MUST NOT 改变用户选择的工作区偏好，MUST NOT 改变聊天车道的工作目录。

#### Scenario: 仓库内自动用 worktree

- **WHEN** 部署的工作区是一个 git 仓库，一次舰队运行开始
- **THEN** 该运行在一份独立 worktree 里执行
- **AND** 其分支或 commit 可在运行结束后被检视

#### Scenario: 非仓库自动退化为普通目录

- **WHEN** 部署的工作区不是 git 仓库，一次舰队运行开始
- **THEN** 该运行在一份独立目录里执行
- **AND** 它 MUST NOT 因为「没有 git」而被拒绝或被降级为共用目录

#### Scenario: 不改变用户的工作区选择

- **WHEN** 一次运行使用工作台结束
- **THEN** 用户的工作区偏好与聊天车道的工作目录与运行开始前相同

### Requirement: 工作台生命周期绑定该次运行并必须被回收

工作台 SHALL 在该次运行以任何终态关闭后进入回收：保留一个可配置的保留期供事后检视，到期即删除。

被强杀或断电留下的工作台（其运行已无对应进程）SHALL 由 sweeper 在一个回收周期内识别并收敛，MUST NOT 永久残留。`git worktree` 后端 SHALL 同时清理其元数据（`worktree prune`），使残留分支登记不无限增长。

#### Scenario: 正常结束后按保留期回收

- **WHEN** 一次运行正常结束
- **THEN** 其工作台在保留期内可被读取，到期后被删除

#### Scenario: 强杀留下的工作台被收敛

- **WHEN** 一次运行的进程被 `kill -9`，工作台目录残留
- **THEN** sweeper 在一个回收周期内识别并删除该工作台及其 worktree 元数据

### Requirement: 工作台占用必须有配额且超限必须如实报

单份工作台的磁盘占用 SHALL 有可配置上限。超限时 SHALL 以显式、可读的方式处置（截断或使该次运行失败），MUST NOT 让单次运行吃光节点磁盘。

处置结果 MUST 被记录下来并可在读面看到，MUST NOT 静默截断。

#### Scenario: 超限不被静默截断

- **WHEN** 一次运行写出的数据超过工作台配额
- **THEN** 该次运行的读数明确报出「超配额」与已用量
- **AND** 节点磁盘不因单次运行被吃光

### Requirement: 每回合的改动必须可归属到那一次运行

系统 SHALL 为每个回合产出该回合改动的文件清单（路径、行数增减），并把该清单归属到该次运行的工作台地址。清单 SHALL 由平台在**运行自己的工作台目录**上测量得出（工作台即该运行的独占目录，故「这个运行改了什么」是宿主侧可答的问题，无需子进程协作）。有 git 时，改动 SHALL 覆盖 git 能看到的全部改动（含 shell 命令产生的改动）；无 git 时，因工作台以空目录开始，改动 SHALL 覆盖该目录内的全部文件（本运行的全部产出），并如实说明覆盖范围。

不可取得时 MUST 显示「未取得 + 原因」，MUST NOT 显示为「本回合没有改动」。

#### Scenario: 有 git 时覆盖 shell 改动

- **WHEN** 一次运行通过 shell 命令修改了一个文件
- **THEN** 该改动出现在本回合的变更清单里

#### Scenario: 无 git 时如实说明覆盖范围

- **WHEN** 工作台不是 git 仓库（空目录起步），一次运行写出了两个文件
- **THEN** 清单列出这两个文件，并说明「无 git：清单为工作台内的全部文件（本运行产出）」

#### Scenario: 取不到不等于没有改动

- **WHEN** 变更记录的采集失败
- **THEN** 读面显示「未取得 + 原因」
- **AND** MUST NOT 显示为「本回合无改动」

### Requirement: 非 git 工作台的产物必须走显式晋升

普通目录后端 SHALL 提供明确的晋升出口（产出物落角色产物目录、结论落报数、文件入资源库），使「要留下的东西」不依赖工作台本身长期存在。

一次运行结束时若存在未晋升的改动，读数 SHALL 报「改动 N 个文件、晋升 0 个」，MUST NOT 报为成功交付。

#### Scenario: 未晋升如实报出

- **WHEN** 一次普通目录运行改了 5 个文件，没有调用任何晋升出口
- **THEN** 读数报「改动 5 个文件、晋升 0 个」
- **AND** MUST NOT 报为「本轮无产出」或「交付完成」
