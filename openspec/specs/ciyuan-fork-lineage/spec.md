# 词元谱系：sub2api 增量 fork 的跟上游治理

## Purpose

萬星·词元以 sub2api 增量谱系 fork 形态运行（对照 ADR-0017 registry 冻谱系），规定
其版本语义、跟上游节奏、分叉纪律与降级条件，使「深度定制」与「定期跟上游」长期并存。

## Requirements

### Requirement: tag 编码上游基线

每个词元发布 tag 形如 `ciyuan-vX.Y.Z-N`：X.Y.Z 为已并入的上游版本，N 为 fork 补丁级；
任意两个 tag 之间可一眼读出上游落后度与 fork 增量数。

#### Scenario: 发布命名
- **WHEN** 词元完成一次含上游 v0.2.16 全量内容的首次发布
- **THEN** tag 为 `ciyuan-v0.2.16-1`，镜像与部署引用同 tag

### Requirement: 月度合并窗

谱系以月度为常规节奏并入上游：合并当期上游 tag、仅限登记缝点内解冲突、通过上游
测试套等价运行与车道测试后出片，并在台账登记当窗事实。

#### Scenario: 常规月度窗
- **WHEN** 月度窗执行且上游有新 tag
- **THEN** 产出新 `ciyuan-vX.Y.Z-N` 发布，台账新增一行（上游 tag、缝点冲突清单、出片 sha、探针结论、merge 用时）

#### Scenario: 上游无新版本
- **WHEN** 月度窗时上游无新 tag
- **THEN** 不产出空发布，台账登记「无上游增量」即可

### Requirement: 安全快车道

上游 release notes 含安全修复（默认凭据/支付回调/爆破/越权类）时，不等月度窗，
立即执行单独合并发布。

#### Scenario: 安全修复触发
- **WHEN** 两窗之间上游发布含安全修复的版本
- **THEN** 在约定时限内（天级）完成合并出片与部署滚动，台账登记触发事由

### Requirement: 只增不改的分叉纪律

fork 自有代码全部位于独立新增包内；对上游文件的修改仅限台账登记的缝点集合；
台账记录每个缝点的位置与用途，缝点集合变更须显式登记。

#### Scenario: 新增能力落位
- **WHEN** 词元新增车道或功能
- **THEN** 实现代码位于 fork 自有包路径，上游文件零修改或仅触碰已登记缝点

#### Scenario: 缝点冲突可预期
- **WHEN** 月度合并遇到冲突
- **THEN** 冲突仅出现在台账登记的缝点文件内；缝点外冲突视为纪律违规，须回查并补登记

### Requirement: 上游回馈优先

普适能力优先以上游 PR 形态回馈（保持可 cherry-pick 的独立提交、签署 CLA），
合入后从 fork 内退役对应本地补丁；fork diff 只许缩小方向的变更不需额外决策。

#### Scenario: 普适补丁回馈
- **WHEN** fork 内某补丁属普适能力（如按 key 用量查询、虚拟用量端点）
- **THEN** 以独立提交推上游 PR；上游合入后的下一个月度窗将其退役并记录于台账

### Requirement: 三月检查点与显式降级

连续三个月度窗记录 merge 用时；单窗超一天即触发显式降级决策（冻谱系走安全单行道，
或车道外提为独立服务），决策与理由记入台账，不允许无决策硬扛。

#### Scenario: 痛感达标触发决策
- **WHEN** 任一月度窗 merge 用时超过一天
- **THEN** 台账触发降级决策条目，记录所选路线（继续/冻结/外提）与理由
