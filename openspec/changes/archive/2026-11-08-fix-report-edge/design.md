# Design — fix-report-edge

## D1 为什么是"派生"，不是"删除"也不是"新建运行时语义"

三个选项：

| 选项 | 代价 / 风险 |
|---|---|
| 从枚举删除 | 要清六语言文案、前端分支、校验/供给面分支；且"报数上行"是真实存在的拓扑，删掉图就少一层结构 |
| 让 report 边真的驱动报数 | 报数通道与巡视上下文已按 `parentId` 走；改成读边 = **两套真相**，且要迁移既有舰队 |
| **让边成为树的投影** | 无需运行时改动、无需迁移；拓扑必然为真；前端零改动 |

选第三条。核心判断：`parentId` 与 report 边如果都表达同一件事，正确做法是**让其中一个是投影**，
而不是让两者并存并祈祷它们一致。

## D2 方向：from 是报数方

UI 渲染 `${name(e.from)} ↑ 报数上行`——"from 向上报"。所以：

- 派生边 = `{ from: 岗位 id, to: 该岗 parentId }`
- 校验判据 = `reporter.parentId === e.to`

第一版把方向写反了（`from: parentId, to: id`），被既有用例
「`report: b→a` 且 b 的上级是 a 应当通过」当场打红——这正是保留既有测试的价值：
它挡住了一次自洽但错误的改动。

## D3 一致声明保留、矛盾声明拒绝

- **允许**声明真实关系：已经手写的舰队不会因为这次改动而无法保存，且读面不会显示两条重复边
  （`expandedEdges` 先看声明里有没有同向的 report 边）。
- **拒绝**矛盾声明：这是本条要消灭的东西——一条说谎的边会误导看图和读 prompt 的人。
  错误文案直接给出真实上级（"B 报给 A，不是 C"），把修法写在错误里。

## D4 运行期不受影响

派生只发生在读面（`expandedEdges` 本来就是 read-time 展开的，supervisor 的隐式派发许可同理）。
`trigger` 边保持原样（它是"节奏物化"的图形态，同样不产生行为）；`dispatch`/`handoff`/`fanout`/`event`
四条带行为的边一概不动。

## R1–R4

- **R1 既有舰队**：声明了真实关系的照常通过；声明了假关系的会被拒——这是有意的破坏性收紧，
  错误文案给出修法。prod 已核查为零声明。
- **R2 模板**：编导随模板下发走同一校验器（既有条款），故模板里说谎的 report 边同样在建队/发布前被拒。
- **R3 边计数**：`validateOrchestration` 返回的 `edges` 现在含派生边，凡按长度断言的测试需
  与之对齐（本次只影响那一处，已改夹具使其声明为真）。
- **R4 重复呈现**：派生与声明同向时只留声明那一条（`derived` 不置位），读者看不出差别。
