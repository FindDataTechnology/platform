# add-principal-facade — Design

## Context

动机见 proposal.md。现状约束（决定了本设计的形状）：

- 运输层全在产：萬星对话车道（登录访客+三层瀑布）、A2A 门面（message/send|stream+
  AgentCard+目录）、delegation A2A（按人归属/按部署者凭据）、pack 发布门（身份戳+版本
  不可变+结构化校验）、在役重部署容量豁免。
- fleet 模板已定义 targetRef 类别体系（pack 预设/既有 persona/既有 cluster/既有 a2a/
  bot/tool）与编导边集——门面的「接待+委派」语义与其同源。
- manifest 现有 `agents[].serving` 声明即部署为 Agent 服务的通道；工具白名单机制
  （allowTools + register-shadow 三层桥）是成熟的工具面收窄手段。
- memory v4 的对话面注入（S5/萬星 spawn）未到——语料 grounding 只能走 pack 内静态承载。

## Goals / Non-Goals

**Goals:**

- 门面成为 pack 上的一种**受识别的 profile**（`facade` 块），全链复用既有机制，发布/
  部署/目录/计费零新引擎。
- 寻数门面（企业/项目/能力三类语料）作为范例走同一路径建成并内部可达。
- 验收含非运营用户同径最小门面。

**Non-Goals（设计级边界，承接 proposal「明确不做」）：**

- 不建独立「门面页」聚合面（v1 入口=目录标识+对话车道 URL；人页聚合留给事项串时代）。
- 不建语料运行时拉取/向检索底座（等 memory v4；v1 语料随版本冻结）。
- 不建计费立场引擎（v1 立场=声明+呈现，机制全映射现行）。
- 不做跨委托人披露边界的细语义（内部粗粒度可见即可）。

## Decisions

### D1：门面是 pack profile，不是新对象类型

`facade` 为 manifest 可选块；带块即门面。备选是新建 facade 实体（注册表+独立 CRUD），
否决理由：①范例同径纪律自动成立——门面 pack 走的就是普通发布门，无后门可开；②版本
不可变、可见性、订阅/安装、部署、容量豁免、计费瀑布全部白得；③新实体必然重造一遍
这些纪律。代价是门面的表达力受 manifest 约束（可接受：接待面本来就是「策展的静态
聚合」）。

### D2：`facade` 块 schema（v1）

```json
"facade": {
  "reception": "<本包 agents[].id，须带 serving>",
  "corpus": ["<本包 skills[].name 子集>"],
  "delegation": [{ "kind": "in-pack | a2a", "ref": "<agentId | a2a 目标引用>" }],
  "stance": "hosted"
}
```

- `corpus` 引用本包技能：语料=技能正文，随版本冻结、走既有校验限值（≤10 技能/正文
  ≤64KB），不发明第二种内容容器。
- `delegation.kind` 收窄为 `in-pack | a2a` 两类（fleet targetRef 六类的子集）：v1 的
  委派语义就是「转给某个 Agent 服务」，cluster/bot/tool 目标等真需求出现再放开。
- `stance` v1 仅 `hosted` 合法（缺省值）：A2A 车道天然调用者自付，不需声明；他值预留给
  外部化时代。
- 校验落点在 facet 发布门（与 tool_list 对拍同位置、同结构化错误风格）：引用存在性+
  类别合法性+reception 须带 serving。

### D3：委派清单的执行面 = 既有工具白名单桥

接待角色的委派工具面按清单收窄：manifest 解析时把清单内目标写入接待角色的委派目标
配置，执行桥（guard+shadow+restrict 三层）沿用。空清单=不挂委派工具（纯接待）。
不新建「委派路由器」——delegation 通道、凭据语义、归属记账全部现成。

### D4：语料 grounding = 技能静态承载 + 版本 as-of

- 接待人设的 system 资源 = `corpus` 引用的技能正文（聚焦运行时组合已有该语义）。
- as-of 呈现：入口/详情显示所部署版本的发布时间（数据源=版本元数据，零新存储）。
- 刷新纪律（范例侧）：快照脚本拉仓内活文档（CONTEXT.md 词汇表、双星路线图与出口
  判据、openspec 在途 change 概览、谦面/萬星目录快照）→ 策展为语料技能 → 发新版 →
  在役重部署。节奏用平台定时任务（cron 既有），周期 v1 定周更，按陈旧度信号再调。

### D5：委托人身份 = 发布者身份戳，双呈现

门面块不携带身份声明；目录/入口渲染 `自述名称 + 身份戳归属`。归属数据全部现成
（publish 时平台戳的作者身份、部署后部署者账目）。自述文案进 manifest 现有
`description`，不加新字段。

### D6：入口与发现 = 目录标记，不建新面

谦面 browse 行与萬星 catalog 条目：块存在即带门面徽标 + 「和 TA 聊」直达链接（现行
`/#/chat/<slug>` URL）。非门面包零变化（渲染分支以块存在为准）。

### D7：范例语料的策展权威 v1 = 单一运营者

寻数门面 v1 语料由运营侧单一策展（谁说了算唯一化）；分域 owner（法律归法律、产品归
产品）是 v2 方向，等第一个「答案口径被质疑」的真实信号再立。此为设计决定非 spec
行为，不进 requirements。

## Risks / Trade-offs

- [语料陈旧误导] → as-of 强制呈现 + 周更节奏 + 人设文案明示「答不了就看截至时间并
  建议问人」；陈旧度信号（入口滞留时长）进 v2 观察项。
- [策展口径争议（门面替组织说话）] → v1 单一权威 + 自述/身份戳双呈现把「谁在说」
  摆明；争议出现即升 D7 的分域方案。
- [委派清单与运行时漂移（a2a 目标下线）] → 委派失败走既有结构化错误如实透传，接待
  人设包含「委派失败如实告知」纪律；不做清单健康巡检（v2 观察项）。
- [`facade` 块被普通包误用刷目录标识] → 块校验要求 reception 真实存在且带 serving，
  误用代价=发布被拒；目录徽标仅服务发现，不涉排序权重（不新增热度信号）。
- [与 memory v4 换底的接缝] → 语料容器是技能正文，v4 到位后 digest 注入是加法（运行
  时注入）不是替换（版本语料仍在），换底不破坏本能力契约。

## Migration Plan

1. facet 发布门 `facade` 块校验先行上线（无块零变化，风险面=纯新增分支）。
2. 目录/入口呈现与委派面接线随后（渲染分支+工具面配置）。
3. 寻数门面 pack 制作、发布、部署、入口验收。
4. 非运营用户最小门面同径验收。
5. 回滚：门面块与呈现均为增量分支，回滚=目录渲染回退+块忽略，已发布门面 pack 退化为
   普通包（agents/serving 语义不受影响），无数据迁移。

## Open Questions

- 语料快照脚本的策展规则（哪些节选、截多长）——实现期在范例制作中定，不影响契约。
- 目录门面徽标的 i18n 文案——实现期定。
