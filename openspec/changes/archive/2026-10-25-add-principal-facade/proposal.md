# add-principal-facade

> 2026-10-25 `/opsx:explore` 三轮定调（评论→agents-native 沟通→门面能力）。立意修正于第三轮
> 之后：不是「内部先行、外部后置」的分阶段，而是**内部即范例、能力面向每个用户**——本 change
> 立的能力是「任意用户可拥有自己的门面」，寻数门面只是走同一条路的第一实例。

## Why

产品沟通的终局形态已定调：原生沟通只有两型——agent↔agent 与 人↔agent，人↔人只作为
escalation 出口（预约会晤）。「想了解我，和我的 agent 聊」缺一块一等能力：**委托人门面**——
任意用户把「知识库 + 工作方式 + 能力（packs/舰队）」聚合为一个可对话的接待面，附计费立场
（我请客 / 你自付）。运输层全部已在产（A2A、萬星对话车道、委派、三层瀑布计费），缺的是
社会层的地址原语。现在做，是因为门面是 agents-native 沟通的第一块砖，且其第一实例
（寻数企业门面）恰好同时充当 M5.3 首批用户旅程的自然第一问（「了解你们」）。

## What Changes

- **新能力：委托人门面（principal facade）**。门面成为一等对象，一个委托人（个人或组织）
  聚合四件事：
  - 接待 agent：persona + 策展语料（知识库 / 工作方式 / 能力自述）；
  - 专家委派清单：深入问题转既有 Agent 服务（走既有 delegation A2A）；
  - 计费立场：复用既有瀑布 / 调用者键机制，作为门面上的可见姿态（我请客 / 你自付）；
  - 门面入口与发现：可分享、可寻址。
- **第一实例：寻数门面**。答三类问题——企业（是谁/做什么）、项目（在干什么/进展）、产品能力
  （有什么能耐/怎么用）。语料以仓内活文档冷启动（CONTEXT.md 词汇表、双星路线图与出口判据、
  openspec 在途 change、谦面/萬星目录）。
- **范例纪律**：寻数门面走与任意用户完全相同的门面创建/发布路径，无平台后门——自营 pack
  同门纪律的重演。范例即样板：每个用户复制的正是这条路径。
- **明确不做**（各有承接）：
  - 事项串原语（跨方耐久锚点：谈到哪/共识了什么/谁批准了什么）——独立 change，本门面先行
    不依赖它；
  - 细粒度披露边界（跨委托人 consent 语义，全局闸 4 的题）——随外部化与场景B 深化解；
  - 对外开门动作（M5 合规线）——另行按 5.1→5.2 推进，本 change 的门面在内部可达面先活；
  - memory v4 digest 换底——语料先手工策展（快而糙，新鲜度靠节奏），v4 的对话面注入
    （S5/萬星 spawn）到位后升级 grounding，不阻塞本 change。

## Capabilities

### New Capabilities

- `principal-facade`：委托人门面——门面对象的组成（接待 agent/委派清单/计费立场/入口）、
  创建与发布路径（用户侧一等动作）、可见性与身份口径（门面代表谁说话、语料新鲜度纪律）、
  第一实例（寻数门面）的验收标准。

### Modified Capabilities

（无——门面复用既有部署、对话车道、委派、计费的 spec 行为，不在本 change 改其 requirements；
若 design 阶段确定入口挂载需要改现有面，届时按流程补 delta。）

## Impact

- **复用为主**：agent 部署（萬星）、对话车道计费瀑布、delegation A2A、pack 发布门——机制
  零新建；主要新面在门面对象本身（创建/配置/发布/入口）。
- **新工作在语料**：企业门面三类语料的策展与新鲜度节奏（活文档 → 接待面）是主要工作量与
  风险位——口径权威（门面替谁说话、谁策展）与文档时效（在途 change/目录热度天天变）。
- **验收形态**：内部同事零培训，经门面入口问答三类问题得到如实、不过期的答案；深入问题
  经委派落到既有专家 agent；寻数门面与一个非运营同事自建的最小门面走通同一条创建路径。
- **下游**：为外部版门面（任意用户对不特定公众，含计费立场的社交化）提供已验证范例；
  事项串、披露边界在此地基上生长。
