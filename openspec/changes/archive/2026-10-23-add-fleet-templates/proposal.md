# Proposal: add-fleet-templates（舰队驾驶舱与模板生态）

## Why

前三刀落地后，舰队已可运营：岗位有业务状态（报数）、有指令边（拍板）、可长期维护（换防/调速/归档）。但两个缺口让它还成不了「用户直接使用的核心功能」：一是**呈现**——管理面是运维视角的树与表，不是创始人视角的驾驶舱（KPI 卡墙、「等你 N 件」红字、部门日报流）；二是**获取**——每支舰队都要从零手组，用户无法一键获得「公司式舰队」这样的成品组织，舰队创建者也无法把自己的组织经验沉淀复用。本 change 补齐这两块：驾驶舱投影 + 舰队模板 pack 化（市场安装/本机导出），完成「直接使用 + 持续维护 + 组织传承」的闭环。

## What Changes

- 新增**舰队驾驶舱**（舰队主视图，单页合并裁决：驾驶舱即舰队页，管理动作内嵌卡片菜单与抽屉，不再设独立运维面）：树形/分区组织图（岗位卡=岗位名+KPI 槽值与趋势+目标值达标色+在岗徽章+上下次节奏或被动标记）、拍板待办顶部横幅（「等你 N 件」高严重度优先）、日报流（各岗位 latest summary 汇流）、舰队健康一览（失联/待补岗聚合）。
- 新增**舰队模板**对象（FleetTemplate）：岗位骨架（含 KPI 槽位与目标值、节奏默认值（可为空=被动岗骨架）、prompt 模板、组织关系）、所需 pack/预设清单、封面元数据；模板以 **pack 形态上市场**（复用既有 pack 市场/安装/凭据链零改动），安装即实例化。
- 新增**实例化器（provisioner）**：模板 → 建 persona（pack 预设）/引用既有对象 → 建舰队与岗位 → 物化任务 → 落驾驶舱；对模板声明的外部依赖（市场 a2a、连接器）缺位时逐项诚实降级（岗位建但标「等连接器」），不整体失败。
- 新增**导出**：用户把现役舰队导出为模板（去所有者/去运行时数据，只留结构与槽位定义），可再上架市场形成生态闭环。
- 模板升级链（v1 裁决）：新版模板**不自动迁移**现役舰队；现役舰队呈现「模板有新版」提示，主人自行对齐（手动换防/调速/重建）。
- 应用中心新增「舰队」类目卡（模板入口）。

## Capabilities

### New Capabilities

- `agent-fleet-cockpit` — 创始人视角驾驶舱投影：组织图/KPI 卡墙/拍板横幅/日报流/健康聚合的读面契约。
- `agent-fleet-templates` — 模板清单格式、pack 载体与市场分发、实例化器（含依赖缺位降级）、现役导出。

### Modified Capabilities

（无——pack 市场安装链按既有契约复用；app-center 卡片按既有类目机制加一类。）

## Impact

- **代码**：`web/src/pages/FleetCockpitPage.tsx`（新）+ 应用中心类目卡；`fleet-template.js`（清单解析/校验）；provisioner（编排 catalog/clusters/fleets 三方 API）；导出端点；pack 清单内 fleet 段的 schema 进 pack-validate 预校验。
- **依赖**：add-fleet-core / report-lane / decision-lane 全量对象与读面；pack-installation / pack-marketplace 既有链。
- **生态影响**：官方首只模板「公司式舰队」（开源/投资/助理三真数据部门 + 电商/内容等连接器空态岗 + 萬星集群混编成员）作为机制的跨平台样板与市场种子内容。
