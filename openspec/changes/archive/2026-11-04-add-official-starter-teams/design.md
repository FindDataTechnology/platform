# Design: add-official-starter-teams

## Context

八步路线的最后一步：前面七步把资产与通路备齐——种子（五枚，en 副轨已填）、官方判定与集合读面
（showcase）、Builder 四员（#5）、官方 pack 改名（#4）。缺的只是「新用户的第一公里」：引导里没有
starter 序列（现有 tour 指向桌面机群步与入门包），说明散在 seeds 的 description 里没有结构化卡，
公开教程（`docs/tutorial.*`）还是旧词表。

## Goals / Non-Goals

**Goals**

- 新用户从「不知道装什么」到「首轮报数可读」有一条被引导、被解释、被验证过的路径。
- 说明卡零第二真源（与种子 manifest 同源），词表全仓一致。

**Non-Goals**

- 不做一键全套安装（安装是逐 pack 显式动作——克制纪律，与 builder 不代发布同源）。
- 不做新用户自动建队（实化即全队暂停+确认点燃的既有纪律不动）。
- 不改种子结构与铸造链（说明卡是 guide 内容模块的呈现，不是 manifest 新字段）。

## Decisions

### D1 · 序列是常量不是存储

starter 序列（哪支首选、一句话定位）落为代码常量/配置，官方集合面与引导共同消费。理由：序列是
产品叙事（推荐次序），不是用户数据；入库反而要管租户差异。

### D2 · 说明卡走 packGuides 既有通道，用测试钉「卡与种子不分叉」

`packGuides.ts` 是既有的 per-pack guide 内容模块（marketplace guide card 机制已消费它）——说明卡
作为五支 starter 的 guide 条目写入，单测断言卡的岗位清单与种子 fleet 段成员数/名一致。理由：
guide card 通道已匿名可读、已随详情呈现，零新面；测试把「卡说三岗实为四岗」这种漂移在 CI 逮住。

### D3 · 首选=客服班组

最小满编（恰 3 岗无引用岗）、节奏最直观（4h 巡检）、且种子自带「凭据缺位如实降级」的示范
（CRM 工具未配置时报「未取得」不整体失败）——新用户第一课正好是平台最核心的诚实纪律。
AI 公司是全景示范但岗位多、引用外部数据源多，作次选。

### D4 · 教程单独成文而不塞进产品内引导

产品内引导管「点哪里」，教程管「为什么与全过程」（含匿名访客视角）。公开教程放 `docs/`（公开仓
快照链路已带 docs/），facet docs 的创建段与官网可链——挂账对侧仓的链接位。

## Risks

- **对侧仓依赖**：registry 落地页的行动入口深链在对侧仓（fd fork），本仓只交付深链目标——
  tasks 挂账，不阻塞本仓交付。
- **教程与 UI 漂移**：教程逐步断言「入口真实存在」靠走查验收（4.2）而非自动测试——接受这一
  维护成本，教程是文档不是契约。

- **市场 id 实证入常量**：五支种子的市场 packId 从生产 facet 逐个查得

  56opYgli…晨报情报站）写入 STARTER_TEAMS——与 packGuides 既有条目同惯例（id 稳定跨版本）。
- **词表门立功（又一次）**：starter 门测试的 v4 词表断言逮到说明卡里「集群引用岗」残留
  两处→改「团队引用岗」。
- HelpDialog start tab 挂序列（role 徽章 首选/进阶示范/领域进阶 + oneLine + 安装纪律句）；
  桌面机群步保留不动。
- 浏览器 e2e 未单写：帮助中心是纯前端面，序列渲染由门测试+typecheck 覆盖，走查班眼见。
