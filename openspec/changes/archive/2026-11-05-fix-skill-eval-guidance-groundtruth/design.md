# fix-skill-eval-guidance-groundtruth — Design

## Context

§15.135 补记的实测发现：盲评 judge 无政策真值时，政策型技能候选的新增政策声明被判「臆造」，而 old 臂既有声明与 control 臂自创值逃过同等质疑——supersedes promote 腿结构性锁死。闸机制本身四分支全部工作正常（8 轮活体），缺的是 judge 的真值输入。

## Goals / Non-Goals

**Goals**

- judge 评审输入增加指导文档真值段（旧 skill 正文 + 新候选正文，盲标）。
- 有据性规则入判据：声明与任一文档一致=有据；两份文档+任务都不含=无据。
- 质量判据不变（正确性/完整性/可执行性），防「文档长=占优」偏置。

**Non-Goals**

- 不改闸判据（candidate best / tie）、不改双钥匙、不改臂构造与盲排。
- persona-eval 不动（角色流判据天然容忍条款差异，A3 全链绿）。
- 不做「技能声明政策需人工备案」类前置门（那是对提案流程的加压，不是对评测的修复）。

## Decisions

### D1. 盲标文档段，与回答标签独立洗牌

指导文档以「指导文档一/二」盲标提供，洗牌独立于回答的甲乙丙洗牌——judge 无法从标签推断「哪份文档喂了哪个回答」。若文档与回答同标，judge 会偏向「回答与自己的文档一致」的臂，盲评失效。

### D2. 有据性=「任一文档并集覆盖」，对称适用

声明有据 ⇔ 该声明内容出现在**任一**指导文档或任务文本中。对称适用于全部臂：control 臂（无指导）自创的政策值由此从「隐性豁免」转为「无据」——纠正实测中观察到的不对称（§15.135：candidate 臂条款被判臆造、control 臂自创分级逃过质疑）。

### D3. 有据性与质量分离，防文档长度偏置

判据文案明确：有据性只回答「声明是否有真值来源」，回答优劣仍按完成任务程度评。否则 judge 会奖励「把文档全文抄进回答」的臂，技能正文膨胀成为博弈方向。

### D4. 文档截断沿 transcript 同规

指导文档过长时按 `clip()` 同参数截断，防超长技能正文撑爆 judge 上下文；截断在提示词构造处一次完成。

## Risks / Trade-offs

- [judge 仍可能误判有据性（模型能力）] → 规则是提示词级约束非硬保证；实测验收锚（§15.135 被拒的 v3 形态候选重评）直接检验。
- [两份文档高度相似时 judge 混淆] → supersedes 的 old/candidate 本就同源相似，文档段按 D4 截断+盲标；判据要求的是「声明有无出处」非「出自哪份」，混淆不改变有据性判定。
- [文档段增加 judge 输入 token] → 实测 judge 调用 ~13-23s（glm-5.3-flash），两个文档段增量 ≤2KB，预算内。

## Migration Plan

1. 单测（judgeUser 构造含文档段、盲标独立性、截断）→ 出片沿公开免费线 → demo 实弹：§15.135 被拒的 v3 形态候选重评，验证政策条款从「臆造」转「有据」。
2. 回滚：滚回上一镜像即全量回退（纯提示词构造变更，无 schema/数据面）。
