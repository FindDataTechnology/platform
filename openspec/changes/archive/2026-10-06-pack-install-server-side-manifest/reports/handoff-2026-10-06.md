## 1. 缺陷背景（为何改传输设计）

- **症状**：壹座 设置→Packs→Store→「Subscribe & Install」对 DAAS 包静默失败（快断连/403），My Packs 空、磁盘零物化。
- **根因实证链**（可复现）：同字节只改一个必失败字段（version=0.5）→ 仍连接重置（内容触发）；39KB 假内容 → 400 到达应用（尺寸无关）；2KB 分块扫描 → chunk 5/18 被 403；前缀二分 → 触发点 `WHERE name='<name>'`（SQLi 规则）与 Python 片段（`from scraw_akshare.database import ...` 邻域）；`<script`/`UNION SELECT`/`subprocess.run`/`curl|sh` → 403。
- **层**：platform.finddatatech.cloud 前置 **SafeLine（雷池）→ Caddy**（infra 文档实证 demo./wanxing. 同栈）。
- 完整证据：本 change `design.md`；finddata 仓 `MCP-REGISTRY.md` §3「市场安装链被 SafeLine 拦截」行；跨会话记忆 `safeline-blocks-pack-install`。

## 4. 改代码前必读的设计点

- 服务端取包**必须复用既有市场代理的身份+令牌构造**（`x-facet-user` 等，见 `gateway/facet-proxy.js`），私有包 owner-scoped 语义（200 vs 404）与市场列表一致；
- 双形态兼容：带 manifest 的 body 走**同一套校验管线**（滚动窗口），manifest 优先取 body；
- 取包失败 = 明确错误 + **零写入**；
- 不动 `installPack` 语义（冲突策略 / per-part report / 升级 / 卸载全部保持）。
