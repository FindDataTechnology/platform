# Proposal: add-teams-hub-formation-board

## Why

综合看板今天是一堆卡片：看不出"团队长什么样"——岗位怎么排、接棒线怎么连、哪条线断了。编排的真相藏在每支团队的驾驶舱里，主人要看全景只能一支支点进去（且切换条体验刚由姊妹 change 修顺）。同时副驾驶（`CopilotDock`）与团队架构师 NL 编边（dry-run diff + 批准纪律）都已在产，却没接到看板上——用户看着阵形想调一笔，够不着手。本 change 给综合看板加**编队视图**（每支团队一张迷你阵形图），点开进既有驾驶舱继续手动编排；看板右侧挂**副驾面板**，对话直达架构师通道调整编排。

## What Changes

- 综合看板新增「编队」视图，与卡片列表可切换（选择持久化）：每支团队渲染迷你阵形图——岗位节点 + 编排连线（沿用 `FleetGraph` 的 kind 着色与分层布局）+ 状态色（在岗/失联/需关注沿用六态口径），异常团队的断线/缺岗在图上直接可见。
- 阵形数据不再逐队拉详情：既有聚合读面 `GET /api/fleets/overview` 载荷扩展每队紧凑阵形摘要（成员节点 + 边），看板一次取齐（N+1 名册教训在前：`fix-session-open-latency` 实测过逐队详情把首帧拖到秒级）。MUST NOT 另造第四份状态计算（沿用 overview 主位条款）。
- 点迷你阵形图 = 直达该队驾驶舱（既有深链语义），手动拖拽编排沿用驾驶舱画布，本刀不新造编辑器。
- 看板右侧副驾面板：`CopilotDock` 以团队架构师聚焦 preset + 舰队上下文（当前看板/选中团队）打开；自然语言调整全部走架构师既有通道（dry-run diff → 批准 → apply），编队视图随编排广播自动重渲。**副驾在看板上不得跳过批准纪律直接 apply**（架构师批准条款在看板侧同样成立）。

**非目标**：不做全屏一张大编排图（团队间超级节点拓扑留待编排产品化下一拍）；不新造阵形编辑手势；不动驾驶舱本体与架构师工具面语义。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `agent-teams-overview`: 新增「编队视图为主位的第二种形态」需求（迷你阵形 + 切换持久化 + 聚合载荷扩展）与「副驾自看板接入架构师通道」需求（批准纪律不破 + 广播重渲）；既有「一点进驾驶舱」「聚合主位」条款保持。

## Impact

- 服务端：`GET /api/fleets/overview` 载荷加每队阵形摘要（members 节点字段 + edges 紧凑形态），既有消费方零破坏（字段增位）。
- Web：`FleetsPage` 综合看板区（视图切换 segmented + 编队栅格）、`FleetGraph` 复用为 mini 形态（尺寸/密度参数化，不改布局算法）、副驾挂接复用 `CopilotDock`（board 上下文指到团队页）。
- 依赖：polish-agent-teams-hub-navigation 先行（切换条常显后，看板↔驾驶舱动线才成立）；六态/异常口径沿用现读面。
- 不动：驾驶舱画布（cockpit-v2/ops-canvas）、架构师三段工具面、编排广播协议。
