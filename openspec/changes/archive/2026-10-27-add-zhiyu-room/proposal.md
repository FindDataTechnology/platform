## Why

「萬星·智语」立项：对话不该只有「一个人对一个智能体」一种形态。真实协作里，人需要把同事、第三方智能体、以及**自己的分身**拉进同一个房间——而分身可以替不在场的主人**值守**，必要时把人呼叫回来。开源与商业世界里尚无任何产品做到「多个人 × 多个智能体同席对话」（Mattermost Agents 让 AI 屈居频道组件、ChatGPT 群聊只允许一个 AI 且不可扩展），这是真空档。平台的四条已投产线（social-bot-channels / principal-facade+a2a serving / wanxing-facade / matter-threads+action-gate）恰好备齐了房间的全部零件，差的只是把它们收拢的那个对象：**空间**。

## What Changes

- 新增「空间」对象（萬星·智语一期，站内）：多人 × 多智能体的实时共席房间，与既有 1:1 会话并存、互不改造。1:1 会话可一键「升为空间」，携带可选历史窗口。
- 在场名单四类就席：平台用户 / 其值守的分身（facade 部署）/ 站内已部署服务智能体（registry a2a 条目）/（本期内不含游客与外部 A2A）。站内直邀 + 通知握手；分身被邀时按其主人的预设策略应答。
- 回合协议（hermes 实证五件套）：@提及定向应答；未点名则全员可答可 pass；分身/智能体的回复**不自动唤醒**其他智能体（熔断）；每人消息触发的智能体应答有硬上限（部署级默认值出厂 3、房间级可覆盖，界外拒绝）；空间**空闲超时自动结束**（可配置）。
- 代席三动词：分身**值守**（主人缺席时分身在场代答、代收待办）→ **呼叫**（亮「需要你」徽标召回本人，或开事项升级）→ **接管**（主人点「我来」拿回发言权）。分身发言全场标注「代 XX 出席」；不可逆对外动作走 action-gate 升级主人批准（复用既有闸，零新机制）。
- 语境与可见性：空间×智能体各有独立远端上下文（复用 a2a contextId 接缝）；空间历史对在场成员全员共享；每个成员与其自己的分身之间有一条**私窗**。
- 计费：发言即计量，各智能体走自家 deployer 的计费键（复用 a2a serving 既有键模型）；人类消息与未发言智能体零计费。
- 站内 UI：空间列表、空间视图（消息流带发送者归因）、在场面板（值守/呼叫/接管）、@补全的输入区。

明确不做（后置 change）：网站嵌入 widget（二期，接待台 2.0）、IM 群桥接（三期）、外部 A2A 智能体入席（三期）、游客链接（二期）、LLM 主持人「议事厅」房型（后置）、完整消息可见性矩阵（后置）。

## Capabilities

### New Capabilities

- `zhiyu-room`: 萬星·智语的空间内核与站内面——空间生命周期（创建/升房/空闲自动结束）、在席成员与邀请握手、消息流与发送者归因、@路由回合协议与熔断、分身值守/呼叫/接管的代席回路、空间×智能体语境隔离、私窗、计费挂钩与站内界面。

### Modified Capabilities

（无既有能力的需求级变更：1:1 会话、session-share、a2a serving、matter-threads 的行为契约保持不动，空间全部以新对象与新路由落位。）

## Impact

- 新模块：`gateway/zhiyu/`（与 wanxing facade 同层）——空间内核、回合路由器、邀请握手、上下文键管理。
- 数据：project database 新增 `zy_rooms` / `zy_room_members` / `zy_room_messages`（消息行**携带发送者身份**，区别于 `chat_messages` 的单主模型）；既有表零迁移。
- 复用接缝：`server/a2a-client.js` 的 contextId 键形扩展为 `room:<id>:<agentId>`；`sendToViewers` 型扇出广义化为空间订阅（不动 1:1 会话的不变量）；通知复用站内未读 + bot-relay/微信订阅通道；计费复用平台计费门与 a2a serving 键绑定。
- 前端：站内新面（空间列表/空间视图/在场面板），既有聊天 UI 不动。
- 词汇终案（用户侧）：空间 / 在场 / 值守 / 呼叫（「需要你」）/ 接管（「我来」）/ 空闲自动结束；代码键用英文 room/member/on_duty/needs_you/take_over。
- 台账：发布后更新 `docs/registry-maintenance.md`（§1 运行表 + §9 发布记录）。
