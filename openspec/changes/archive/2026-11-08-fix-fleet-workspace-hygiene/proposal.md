# Proposal — fix-fleet-workspace-hygiene

## Why

巡逻纪律自 2026-10-29 起就写着「不要再写工作区历史文件、也不要读旧的」，而产线同一个 cell 的共享工作区
今天仍是 **358 个文件 / 26MB**，全是岗位自己写的 `DUTYLOG-*` / `BOARD-ENTRY-*` / `TICKET-DISPATCH-*`。

这份体量正是 P0′-1 的直接成因（explore 已取证）：单 cell 的 `tool/result` 共 **47MB / 5728 条（均 8KB）**，
主要就是把这些文件读回来；逐条累积把 128K 窗口占满 → 反复 compaction → 600s 预算烧完 → 零产出。

为什么规劝没用：**岗位不知道代价**。它写文件是因为怕下一轮忘（而平台其实每轮都在注入它的往轮摘要），
它读文件是因为以为那才是“完整档案”。纪律段说了“不要”，却没说“为什么不必”和“读了会怎样”。

## What Changes

- 巡逻纪律段末尾追加**一行可核对的事实**：`工作区现状：已累积 N 个文件（M MB），其中你自己的往轮文件 K 个`，
  并点明：平台已保存往轮并在上文给了摘要 → 再写是重复、读旧的是过期副本、这些字节**直接扣本轮上下文预算**。
- 读数由平台读时测得（`readdir` + 大小，60 秒缓存、只算顶层文件、任何失败返回 null），纯增量、无删除。
- 无读数（空目录/读取失败/宿主未提供）时纪律段**逐字节不变**；边回合不带该行（它们本来就没有纪律尾段）。

## Impact

- Affected specs: `agent-fleet-report-lane`（MODIFIED：巡视上下文注入 + 3 个场景）
- Affected code: `server/fleet-context.js`（`renderWorkspaceHygiene` + 尾段拼接）、`server.js`（provider）
- 无迁移、无新表、无新 env；不动 dsh、不动任何工具的输出、不删任何文件。
- 诚实的边界：这是**让代价可见**，不是硬约束——平台无法禁止 dsh 内建 `write`（patch 面九类无此旋钮）。
  但它把“为什么要克制”从口号变成了本轮就能验证的数字。
