# Design: polish-desktop-fleet-parity

## Context

A 系（fleets/boards/cron/驾驶舱）对桌面零门控，随同一份 web 构建物发出，托盘/
管家常驻已由既有 spec 兜住——本 change 不是补功能面，而是**给桌面用户一条从
零到「跑起来的舰队」的路径**，并把种子供给从"只有市场"扩成"含离线"。侦察
要点：`agent-fleet-templates` 已有仓内种子真源与守恒测试（清单文件为真源、
市场 pack 只是铸造产物），首启 tour 现有三步且契约严格（不阻塞、可跳过、
done 标记），`FleetTemplateWizard` 与 pack 详情件已在 web 侧可复用。

## Goals / Non-Goals

**Goals:**
- 桌面首启能把用户带过「装样例 → 建队 → 跑一轮 → 见产出」四步，离线也可。
- 模板供给双道（市场 + 离线 bundle）在应用中心与实例化器同语义，无分叉。
- 种子唯一真源：仓内清单；预置 bundle 只是它的烘焙产物，登记≠安装。

**Non-Goals:**
- 新造种子内容（复用仓内既有种子真源）；B 系集群的部署（归
  `add-local-fleet-control-plane`）；bundle 格式与烘焙管线本体（归
  `add-offline-pack-supply`）；tour 三步骤文案重写（只追加桌面步）。

## Decisions

### D1 tour 追加步而非改写三步契约

浏览器契约（恰好三步）保持逐字不变；桌面步以**追加**方式进 tour（preload
bridge 判定），复用既有交互契约（卡片不挡操作/Escape/done 标记）与既有
帮助中心重开入口。替代项「把三步改成四步」会动浏览器行为与既有 e2e 断言，
无收益，否决。

### D2 种子唯一真源：仓内清单，烘焙产物带进安装包

预置 bundle 由 `add-offline-pack-supply` 的 predist 从**仓内种子真源**烘焙
（fleet 段语义一致由守恒测试与构建期校验双钉）。cell 首启只做一件事：把
预置目录登记为「可导入源」（读面 + 引导步的默认选中项），**不安装**——
安装保持显式确认（与本期「样例安装仍是一次显式确认」scenario 对应）。替代项
「首启自动装样例」会越过 consent 口径且让空态语义变浑，否决。

### D3 引导步逐段降级，与实例化器既有降级同源

四步串珠里，只有「取样例」在一处有双源（预置 bundle 优先、市场兜底——
断网走前者，无预置走后者）；「实例化」与「跑一轮」完全走既有实例化器/回合
链路的现有降级（依赖缺位逐项降级、待确认启动态）。不新增降级语义，只做
编排与呈现。失败点精确到步（哪一步卡住就给哪一步的引导），不整段报错。

### D4 桌面差异点普查（spike）先做，修与挂账分开

清单（侦察推断，spike 逐条实操核对）：(a) auth off 的单用户身份
（`owner@local` 语义）在建队/boards 归属上的实际表现；(b) cron 时区与停机补跑
在桌面本地时区的行为；(c) 引导步与「关窗即驻留」的交互（引导中关窗再开）；
(d) boards/驾驶舱空态的引导文案；(e) 无登录跳转路径。逐条判「修」或「挂账」，
结论补记进本 design 与 tasks。**不把普查做成开放式任务**——每条都要有判定。

### D5 见证乘既有轨，不新建车道

双平台一幕（装→首启→样例舰队跑一轮→boards 见产出）挂到
`automate-nonweb-acceptance` 的 installer-e2e 轨；win 默认腿必跑，mac
dispatch 腿必跑（本期 D5：双平台眼见才算过）。

## 桌面差异点判定（spike 1.1，代码级核对 + 落地证据）

五项逐条判定（每条都要有结论，不留开放式任务）：

| 项 | 判定 | 依据 |
|---|---|---|
| (a) 单用户身份 owner 语义 | **现状可用** | 桌面 auth 关时统一回落 `owner@local`（packs.js viewer fallback、fleet/boards 路由同源），未发现同一台机器上两个身份并存；不需改 |
| (b) cron 时区与停机补跑 | **现状可用** | cron 记录自带 tz，补跑由引擎既有 catch-up 覆盖（cron-downtime-catchup 已上产）；桌面跑的是同一份 cell 代码，无桌面专属分支 |
| (c) 引导步与「关窗即驻留」交互 | **现状可用** | 引导是页内状态，关窗即驻留托盘（desktop-fleet-console 既有 spec）；重开窗口回到会话，引导不与驻留互斥 |
| (d) boards/驾驶舱空态 | **本 change 补** | 本机集群区新增「无可部署候选」空态（`fleet-candidates-empty`）+ 容量引导，取代旧的恒空目录区 |
| (e) 无登录跳转路径 | **现状可用** | 桌面 auth 关时无 /login 跳转；纯浏览器落桌面专属说明页（既有 spec 覆盖），不需改 |

结论：**A 系在桌面上的产品面缺口只有「从零到跑起来」的路径**，不在身份/时区/登录；
本 change 因此把力气全放在引导步 + 预装登记 + 离线模板同路。

## Migration

- 无数据迁移。新增：预置 bundle 登记读面 + tour 步骤标记（既有 done 标记
  语义扩展不破坏：老标记只表示三步骤完成，桌面步独立键）。
- 无预置 bundle 的旧安装包：引导步自动降级到市场路径（联网）或给明确引导，
  不显示坏态。回滚 = 撤登记读面与引导步。

## Verification

- 单测：预置登记读面（有/无预置目录两态）；tour 步骤选择逻辑（桌面/浏览器）；
  种子烘焙与守恒联动（预置 bundle 的 fleet 段与仓内真源一致）。
- e2e：installer-e2e 轨一幕（含 skip 路径与显式确认断言）；浏览器 tour 仍三步
  （既有断言全绿）。
- 手动：win/mac 真机各走一次首启引导（含断网分支），截图入账；spike 五项判定
  表随 change 归档。
