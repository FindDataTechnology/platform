# Design — fix-fleet-descendant-reports

## D1 为什么走注入而不是加一个「读子树报数」工具

两条路都能解决「祖辈看不见孙辈」：

- **加工具**（如 `subtree_reports`）：不改注入契约，但每轮舰队回合的工具清单都多一件，
  且岗位**得知道**要调它——一个不知道自己被蒙住的岗位不会去调。本轮巡视拿不到就是拿不到。
- **走注入**（本 change）：自动、无需岗位配合，和「报数就是本轮的完整输入」这条纪律一致。

选注入。代价是改了 `agent-fleet-report-lane` 的既有约定（只注入直属下级），
因此按 OpenSpec 走 MODIFIED 并同步更新了钉住旧契约的那条测试。

## D2 为什么只加一层紧凑块，而不是把整棵子树铺平

直接下级是巡视的**主材料**（完整块：槽值+趋势+阻塞+摘要+资源数）。更深层是**背景**：
它要回答的是「底下有没有事」，不是「逐岗对账」。所以紧凑块去掉趋势（省 N 次 prev 查询）
与受管资源计数，只留槽值/阻塞/摘要/时间，并在标题里写清层级与路径——
让模型能分清「这是主编的报数」和「这是撰稿（主编的下级）的报数」。

## D3 独立子池：直接下级永远优先

预算顺序：header → 直接下级（4KB/块，24KB 池）→ **更深层（≤6KB）** → 本岗位往轮 → 执行健康 → 决策 → 记忆。
更深层排在本岗位视图**之前**：它仍然是下级报数（spec 已定「下级段优先于本岗位视图」），
但它有独立上限，所以即使它满载，也只会吃掉自己那份 6KB。

## D4 两层舰队逐字节不变

`collectDeeperDescendants` 在没有第 2 层后代时返回空数组，整段不渲染——
连标题、截断标记都不出现。现网 6 套官方模板全是两层（`docs/fleet-templates/*.seed.json` 实测），
所以这条改动对它们零影响；测试 2 专门钉这一点。

## D5 截断必须说出来

「另有 N 个更深层岗位因条数或总量上限未注入」——部分列表不说清，读起来就是「舰队就这么小」。
同理子池连 200 字符都放不下时直接写「…（更深层报数因总量上限截断）」，不输出三个残字。

## D6 遍历的安全性

BFS + visited 集合：`parentId` 成环（手改库、导入坏模板）不会让巡视回合挂死；
根节点标题从 `members` 里取（用于路径前缀），取不到则退回 id。

## Risks

- R1 上下文变长 → 触发上限：已由独立子池 + 条数上限封住；总量上限的原有核算把 deep 段计入 `used`。
- R2 信息越级（绕过层级问责）：只注入**事实**（报数值/阻塞/摘要），不注入建议；
  层级仍是通过谁向谁报数来体现，这条只补「祖辈原本完全看不到」的洞。
- R3 排序不稳定：BFS 按 `listMembers` 的 `sort_key` 顺序，同一份数据输出一致。
