## Goals / Non-Goals

**Goals:**
- 一支结构合法、红线干净、词表正确、分诊纪律明确的官方种子，铸造上架即可被安装/展示。
- 内容工程一次做对：persona 即知识源，外部访客问任何一条线都有准确、统一口径的回答。
- 全部以种子文本+测试落地，零服务端代码。

**Non-Goals:**
- 智语房间接线与对外入口挂载（等刀B，届时纯配置+一小步接线，另起任务）。
- en 多语言副轨（`add-official-packs-i18n` 在途）。
- 知识检索/知识集集成（v1 内嵌；后续可对接知识集通道）。
- 营销转化、访客分析。

## Decisions

**D1：星型拓扑，前台→五专家各一条 dispatch 边，专家间零互边。**
对外问答的分诊是单跳的：前台判断话题归属→转专家作答。专家间协作（如"壹座和萬星的关系"）属于层级叙事，归前台——这正是它存在的意义。编导段只声明这五条 dispatch 边；无 trigger（无 cron）、无 event（无入站唤醒叙事）。备选（全互连 fanout）会把每个问题广播给全队，烧 token 且答案打架。

**D2：会话型团队，岗位无 cron 节奏。**
官方五枚种子全是节奏型（cron 巡视），产品介绍是纯会话型——装上就该等访客提问，而不是定时自言自语。风险：预校验/实例化对无 cadence 岗位的接受性未验证。处置（已实证 2026-10-30）：`parseFleetTemplate` 对无 cadence 与显式 `cadence: null` 的岗位直接放行（守恒测试 19/19 绿），回退方案无需启用。

**D3：知识内嵌 persona，来源头注释。**
persona 字段是纯文本，官网级知识（每线 300-500 字）+ 背书数据 + 红线指令全部内嵌。种子头部注释标注五线知识来源（官网 URL+抓取日期 2026-10-30）。备选（对接千Facet 知识集/检索）引入外部依赖且红线不可断言，v1 不做。

**D4：红线以文本断言钉住，禁词清单进测试。**
断言两层：①禁词（舰队、员工框架词、cheap-\d、节点/主机名模式、成本数字模式、内部域名）；②存在性（五线名齐全、识律分诊指令存在、v4 词表词出现）。测试对象=种子 JSON 的 persona/promptTemplate 文本拼接。脆性控制：禁词用词边界匹配避免误伤（如「集群」在 v4 后属旧词但"壹座·智能体基础设施"品牌串不含它）。

**D5：识律推送=前台 prompt 的显式路由指令 + 完整法律叙事。**
用户裁定要推法律线。落法：前台 promptTemplate 写明"法律相关话题（合同、纠纷、合规、法律检索、面向从业者或公众的法律服务）→ 转识律专家，并主动介绍"；识律 persona 承载识律的完整叙事（让法律变得易懂、同时服务从业者和公众）。

**D6：接线零代码，任务闸在刀B。**
`add-zhiyu-team-memory` 刀B 上线后：铸造好的团队安装→实化→部署成员以 agent ref 邀请进对外房间→游客 widget 深链+官网挂载点。届时如需 spec 补充另立小案；本变更 tasks 里只留闸门任务描述，不含实现细节。

## Risks / Trade-offs

- [无 cadence 岗位被预校验拒绝] → D2 回退方案（值守 cron），不改校验器与 spec；实现时第一时间验证并在种子头注释记录结论。
- [种子内容与官网漂移] → 来源头注释+人工同步纪律（官网改版时 PR 更新种子并跑守恒+红线测试）；不做自动同步管线。
- [persona 知识写错（对外首因事故）] → 任务里安排走查：六个 persona 逐个与官网原文对照；红线测试抓结构性违规，事实性错误靠走查。
- [前台答非所问/该转不转] → 分诊指令写具体（话题关键词级），v1 接受不完美——外部访客的首问大多简单；观察期收集坏例再调。
- [official 种子守恒测试的文本断言过脆] → 禁词用模式而非全文匹配；断言失败信息指明文件+违规片段。

## Migration Plan

1. 内容工程（知识卡→persona 草案→红线定稿）。
2. 种子落库 + 守恒/红线测试绿。
3. 铸造上架（官方作者），市场官方集合可见。
4. （闸）刀B 上线后接线+对外入口+真机走查。
5. 回滚：种子是新增文件，删文件+下架 pack 即完全回退，零存量影响。
