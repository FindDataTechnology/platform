# Design: add-trading-starter-and-entry-paths

## Context

见 `proposal.md` — Why。三条现状约束：

1. **序列是呈现层**（现有 spec 已明确：不强制顺序、不改安装语义、不产生自动安装）。第六支只是
   往这个呈现层加一项，不引入任何新机制。
2. **说明卡与种子同源**（现有 spec：「数据与种子 manifest 同源，零第二真源」）。所以卡上关于
   五岗、节奏、前置项的描述必须来自种子字段，不能在卡里另写一份散文。
3. **市场已有 9 个投研交易 pack**，其中 6 个是套件（能力）、2 个是团队（三镜头、投研晨会）、
   1 个是 fleet 模板（投研晨会种子）。"装哪个"的困惑来自**套件与团队混在同一个市场分类里**，
   不是缺内容。

## Goals / Non-Goals

**Goals:**

- 让"该装哪个"能用一句话回答，且答案在序列、说明卡、教程三处零矛盾。
- 让交易这件事有一个按节奏跑的入口，而不是只有一个对话式套件。
- 把纸面边界与"不行动的条件"写在用户第一眼看到的地方。

**Non-Goals:**

- 不改市场分类结构（不动 `marketCategory` 枚举）。
- 不合并或下线任何既有 pack。
- 不做自动化推荐（"根据你的画像推荐装哪支"）——那是另一个能力。
- 不涉及编成、风控、账本的实现（在另一仓）。

## Decisions

### D1 第六支放在"执行进阶"而不是重排前五支

既有次序（客服 → AI 公司/内容流水线 → 投研晨会/晨报情报站）是一条"从最小满编到领域进阶"的坡度；
交易舱的门槛最高（要权重、要阈值、要价格口径），放末尾最自然。

- 备选（把交易舱提到第二位，因为它最"酷"）：会把新手直接推到最容易失败的一支——前置项没配好就
  什么都不发生，而新手无法区分"没配好"与"坏了"。
- 备选（不进程序列，只在市场里补描述）：序列是唯一有推荐次序的面，不放进去就等于没有指引。

### D2 四个入口按"能力 / 一次 / 持续 / 执行"四象限分工

| 入口 | 形态 | 一句话 | 什么时候用 |
|---|---|---|---|
| 套件（个股投研/估值/宏观/行业/轮动） | 能力 | 给已有 agent 加手艺 | 你已有团队，想让它会做投研 |
| 投研三镜头 | 团队·一次性 | 一个问题三个角度审一遍 | 要拍一个判断，需要质询 |
| 投研晨会 | 团队·持续 | 每个交易日出观点 | 要持续盯盘、出晨报 |
| 投研交易舱 | 团队·持续+执行 | 观点变仓位，纸面执行并复盘 | 要让观点落到持仓上 |

这个分工的价值在于**互斥性**：每一格都有一个别人答不了的用途，所以"装哪个"不再需要比较优劣。

- 备选（按"专业度"排序）：专业度不可比，且会暗示"高级的替代低级的"。
- 备选（只写交易舱，其余不提）：用户装完晨会仍然不知道下一步。

### D3 升级路径写成"叠加"不是"替换"

晨会（只研究）→ 交易舱（研究+执行）是叠加：晨会的观点可以喂交易舱的组合岗，但晨会自己仍然
独立出报。写成"替换"会让人以为装交易舱就该停掉晨会，而实际上两边共用研究技能、成本几乎为零。

### D4 卡上的"不行动条件"必须与另一仓的实现一致

四条不行动条件（未收到合法权重 / 阈值未配置 / 风控触达 / 价格水位过旧）来自
`finddata/openspec/changes/add-investment-trading-fleet` 的 spec。本 change 的卡文案必须引用该
清单而不是自己重写；那边改了，卡随之改（在任务里写明这条对位关系）。

- 备选（卡上写"由系统自动风控"）：模糊表述会让用户以为有兜底，而实际上缺配置就是不下单。

## Risks / Trade-offs

- **两支团队听起来重复**（晨会 vs 交易舱）→ D2 的四象限表格 + D3 的叠加表述；验收要求文案里
  两者各有一句"什么时候用"，且互不覆盖。
- **卡文案与种子漂移**（既有 spec 已防，靠同源供给）→ 卡文案里的岗位清单与前置项直接从种子字段
  渲染，不手写第二份。
- **纸面边界被写成免责声明一句带过** → 要求写在定位句与卡上两处，且验收做字符串断言（含"模拟盘"）。
- **市场里 9 个 pack 仍然让人困惑** → 本 change 只解决"入口层"；套件层的取舍靠 D2 表格的
  "什么时候用"列，不靠删减 pack。

## Migration Plan

1. 种子 `invest-trading-fleet.seed.json` 由另一仓的编成落地后同步进 `docs/fleet-templates/`。
2. 卡文案（与种子同源渲染）→ 市场详情匿名可读。
3. 序列呈现面加第 6 项（first-run 引导 / 帮助中心 / 官方集合面三处同源）。
4. 教程补入口分工与升级路径段。
5. 验收：匿名打开三个呈现面 + 教程，确认六支齐全、文案互不矛盾、交易支带"模拟盘"。

回滚：序列项是呈现层开关，摘掉第六项即回；卡与教程段落可单独回退。无数据迁移。
