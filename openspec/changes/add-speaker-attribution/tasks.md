## 1. 上游能力实测（已完成，结论见 design 附录 A）

- [x] 1.1 用一段两人对话音频打 `/api/voice/transcriptions`，分别试 `response_format=json` / `verbose_json` / `diarized_json`；**结论**：`json` 与 `verbose_json` 都只回 `text`（`verbose_json` 被**静默忽略**），`diarized_json` 回 400 —— 词元车道今天既无 diarization 也无分段/时间戳。原始读数与探测方法已记入 design 附录 A（合成音频，不含用户数据）
- [x] 1.2 确认它是否区分不同人：**不区分**，响应里没有任何 `segments`/`words`/speaker 字段。因此按预案把主路改为 design D8「按流归属」（每路采集 = 一个人），diarization 降级为将来可选证据源。判据留在附录 A：探测脚本可重跑，将来只改归一层的「上游形状 → 我们的形状」

## 2. 转写归一与逐字节降级（服务端）

- [ ] 2.1 `POST /api/voice/transcriptions` 接受可选分段开关（缺省不请求），开启时向上游请求分段形状；验证=不传开关时响应字段集合与改造前逐字相同（`scripts/test-voice-transcriptions-shape.mjs` 用固定桩上游比对 key 集合与 body）
- [ ] 2.2 服务端把上游分段归一到唯一形状 `{ text, segments:[{startMs,endMs,speaker,text}], degraded?:{reason} }`，MUST NOT 把上游原始结构泄给调用方；验证=同一份上游载荷经归一后字段固定，且不存在上游专属字段名
- [ ] 2.3 降级路径：上游无分段 → 一段 `speaker=UNKNOWN`；分段结构不合法 → 一段 `speaker=UNKNOWN` + `degraded.reason=upstream_malformed_segments`；两种情况都返回 200 且文本完整；验证=三条注入用例（无 segments / 缺偏移 / 乱序）全绿，且断言的文本与上游整段文本逐字相等
- [ ] 2.4 明确不编造标签：`speaker` 与 `personId` 是两个不同字段，响应里不出现「这条声音属于某人」的推断字段；验证=响应 schema 断言里 `personId` 只可能出现在归属接口，不在转写响应中

## 3. 采集链路携带分段（默认不影响旧路径）

- [ ] 3.1 采集分片请求转写时带分段开关，并把 `segments` 落到分段记录（新增可空 `speaker`/`startMs`/`endMs`）；验证=跑一段双人音频的采集，库里分段行数 = 分片数，`speaker` 非空且标注与任务 1.2 的观察一致
- [ ] 3.2 归并按偏移对齐、以文本为准校对，成员为「说话人 + 文本」的片段序列；上游分段与文本不一致时退整段并记原因；验证=既有归并用例（不重不漏/边界不吞字/静音片不产空行）仍全绿，新增一条「分段错位」用例断言退货而非硬拼
- [ ] 3.3 导出与入房消费同一份分段：有标签时在段边界体现换人，全未知时输出与今天的纯文本线逐字相同；验证=两种形态各一条断言，后者与改造前的快照逐字比对

## 4. 身份归属（只有两个合法来源）

- [ ] 4.1 归属函数：输入（采集流标识 + 本场证据）→ 输出（`personId | null`、等级 `session|bound|anonymous`、`reason`），纯函数、无 I/O；验证=真值表用例覆盖三类证据与「无证据」分支，且断言函数内部不读取任何音频特征
- [ ] 4.2 **按流归属（主路，见 design D8）**：每路采集流绑定一个参与者/席位，`speaker` 由**流的来源**直接得出，不做任何声音分析；验证=两路采集同场录音，归并产物中两段分别标到对应的人，且断言实现里不存在任何音频特征比对调用
- [ ] 4.3 `session` 来源：本场声明被接受后该流归给声明人，且**只在本场有效**；验证=同一参与者在下一场会话中重新变回 `anonymous`
- [ ] 4.4 负向守卫：不得调用任何声纹/音色比对；不得把上一场的归属带入本场；验证=`grep` 断言归属模块不引用任何声纹服务，且跨会话用例结果为 `anonymous`（先证明这条用例能红：注入「复用上场的映射」应使它失败）
- [ ] 4.5 混录场景如实失败：一个房间只有一路麦时，无法按人归属，全部落 `anonymous` → `needs_confirmation`；验证=单流混录用例断言没有任何一段被标成具体某人，且产物进入待确认（MUST NOT 用意图匹配补足）

## 5. 接入既有路由（消费侧零重写）

- [ ] 5.1 把归属结果作为 `attribution` 信号喂给 `gateway/zhiyu/voice-router.js`：`session`/`bound` 走默认接收方，`anonymous` 落 `needs_confirmation`；验证=`scripts/test-voice-routing-attribution.mjs` 覆盖四种组合（mention+归属、无 mention+可信归属、无 mention+匿名、归属与意图冲突），断言归属与 `mention` 冲突时 `mention` 仍赢
- [ ] 5.2 确认归属不进权限/计费/可见性：验证=同一段话在有归属与无归属两种情况下，可见性与权限判定结果逐字相同（两条断言并列）
- [ ] 5.3 待确认交互只影响本条消息、不形成记忆：验证=连续两条匿名消息各自需要确认，且第二次不会自动套用第一次的选择
