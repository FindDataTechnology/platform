# 供给域整体方案 —— 谦面升格为智能体供给域（伞文档）

> 2026-11-04 `/opsx:explore` 定案。起因：壹座智能体构建器、agent 站（素材广场）、谦面三面功能重合；
> 用户裁定整体方案**不受现有实况约束**，按最优模式定，且三面应归到谦面之下。
> 与既有文档的关系：本文是供给域的**新伞文档**，取代 `facet-wanxing-roadmap.md` /
> `facet-market-roadmap.md` 中「谦面 = pack 市场供给面」的定位（轨道文档的历史记录不动，
> 后续执行以本文为准）；`yizuo-platform-roadmap.md`（壹座）与萬星轨道随边界重划修订。

---

## 0. 一句话

**谦面从「pack 市场供给面」升格为「智能体供给域」：智能体作为素材/产品的一切——
创作、试跑、发布、目录、理解、获取、分发、计费——全部归谦面；壹座退为运行域
（智能体在干活的地方），萬星是服务域（智能体对外服务的地方）。**

分界原则：**素材静止归谦面，智能体工作归壹座/萬星。**
（artifact-at-rest vs agent-at-work）

---

## 1. 为什么这个模式最优（战略论证）

1. **双边网络效应需要一个门面。** 创作者 × 消费者 × AI 客户端是平台的核心回路，
   回路必须收敛在一个品牌、一个漏斗里。三个门（谦面市场/构建器供给区/素材广场）
   讲同一批素材，等于自己稀释自己。
2. **创作进供给域，获客漏斗才完整。** 外部创作者从「在门厅看到一个智能体」到
   「自己 fork 一个改改发布」应该全程不离开供给域、不需要先成为壹座用户——
   这是 npm / App Store Connect / GPT Store 的共同形状。壹座是 pro 级运行台，
   不该是创作的入场券。
3. **AI-native 是护城河。** 机器面（llms.txt / catalog.json / marketplace.json）
   静态化 + 注释层全物种契约 = 外部 AI agent 可直接消费的目录，这是别家市场没有的。
4. **关注点分离让三方都变纯。** 谦面=素材静止面，壹座=工作面，萬星=服务面。
   各自的产品叙事、可用性边界、迭代节奏都因此清晰。
5. **读路径永不下线。** 目录、机器面、门厅全部由发布事件再生成、CDN 直出，
   动态服务挂了，公开的供给域照常服务（plaza 已实证此模式）。

## 3. 七条裁定

### D1 一个素材脊柱

五物种一个登记处、一个注释层、一个生命周期、一个可见性模型。现 registry
（MCP/skills 真源）与谦面 store（pack 真源）合并为供给脊柱的内部组件，谦面是
它唯一产品面。**杀死三目录**：壹座技能柜/MCP 柜的 bundled `market-catalog*.json`
策展副本废弃；一切目录呈现（橱窗/门厅/壹座内嵌/机器面）都读脊柱投影。
facade 不再从 pack badge 推导——萬星实例真源入脊柱（带状态/出处）；数据锚接
DAAS 真源。

### D2 创作面迁入（构建器归谦面）

`/studio` 三栏工作区与 `/agents` 门面的创作半边（构建区/我的创作）整体迁入谦面，
成为供给域的 Studio 面。**试跑不依赖壹座**：供给域自有 ephemeral 预览沙箱
（限额、不落库），真实执行才落到壹座/萬星。壹座侧只保留「装进我的工作台」动作。
创作者全程不需要壹座账号——漏斗从门厅直通发布。

### D3 读路径全静态，写路径唯一动态

目录 API、marketplace.json、llms.txt、catalog.json、每素材自足页全部由发布事件
触发再生成、CDN 直出（plaza 已证明）。动态服务只承载：发布、策展、studio、计费。
公开的供给域读路径永不下线。

### D4 门厅制 + 域名归一

`agent.finddatatech.cloud` 升格为整个供给域的公网正门：静态门厅在根，橱窗/工作台/
控制台/文档挂在同一域下。`facet.finddatatech.cloud` 退役为重定向（CLI 兼容期保留
机器面 301）。对外只有一个品牌家族：**智能体市场**（门厅=智能体广场，工作台=
智能体构建器，命名沿 2026-10-30/11-01 词表裁定）。

### D5 发布一条路，注释即门禁

manifest 发布 / cell 组装发布 / 实例登记全部同一身份闸+同一校验（现状已同 gate，
收敛为一套 UX）。发布时注释层全物种强制，plaza 的六条 ai_readable lint 上移为
发布门禁。版本不可变快照 + changelog + 订阅者跟新（现状已具备，全物种铺平）。

### D6 身份一张票

统一 IdP（已成立），作者身份由脊柱落戳（已成立，manifest 不自带身份声明）。
门厅/橱窗/工作台/控制台/壹座/萬星一个身份贯穿；跨端安装（六客户端+壹座）
同一票据。

### D7 调优留壹座，实例→草稿有晋升通道

针对**在跑系统**的行为调优（preset 调整、skill 自进化、记忆）留在壹座——它调的是
「工作中的智能体」不是「素材」。当调优结果值得固化为新版本时，走晋升通道：
fork 实例状态 → studio 草稿 → 走发布闸。创作与运行之间双向有桥、单向闸门。

## 8. 风险与挂账

- **facet. 域退役兼容**：已分发客户端可能内嵌 marketplace.json 旧 URL——保留
  机器面 301 兼容期，回归六客户端后再撤。
- **预览沙箱边界**：限额（token/时长/无持久化）要立 spec，防沙箱变成免费算力口。
- **晋升通道语义**：实例状态哪些可 fork 进草稿（记忆？preset？）需单独探索定案。
- **调优面的独立门面**：壹座侧调优目前寄生在 /agents 四区里，四区解体后需要
  给调优一个明确的壹座原生入口（挂 workspace 语境）。
- **伞文档关系**：`facet-wanxing-roadmap.md` 与 `facet-market-roadmap.md` 的谦面
  轨道定位以本文为准，两文档需加指向本文的头部注记（挂账，随 W1 change 一并提）。
