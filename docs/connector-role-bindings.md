# 角色绑定怎么用（包声明角色 · 客户选系统）

> 面向产品 / 售前 / 客户成功。技术细节见 `openspec/specs/connector-bindings/spec.md`
> 与 `openspec/changes/add-connector-role-mapping/design.md`。

## 一句话

**包只说"我要一个 WMS"，客户说"我的 WMS 是旺店通"。** 平台负责把这两句话对起来，
然后照常授权、照常注入，不新增令牌种类。

## 为什么要有这一层

以前包里写的是 `provider: "kingdee"` —— 固定的连接器目录 service id。这有两个问题：

1. 目录里没有的品牌（客户自建的 WMS、区域性的 SaaS）写不进包；写了也是永久"未知 provider"。
2. 同一个行业模板卖给十家客户，仓库系统不可能都一样。每换一家就要改包、重发、重装。

角色绑定把"需要什么"和"用的是哪个"拆开：包声明角色（`wms`、`carrier-portal`、
`supplier-portal` 这类业务词），客户在自己的连接器里选定实际系统，一次选定对该客户所有包生效。

## 三种状态，三种修法（别混）

| 状态 | 客户看到 | 真实含义 | 该做什么 |
| --- | --- | --- | --- |
| `unmapped` | 待选系统 | 还没说自己在用哪个系统 | **选一个**（不是去连接，也不是产品不支持） |
| `unwired` | 能力缺口 | 选的那个系统，目录里的动作面覆盖不了包要求的操作 | **换一个系统**；换不了就是真缺口，如实说 |
| `missing` | 未连接 | 选了，但这个系统还没在连接器里连上 | **去连接** |
| `satisfied` | 已接通 | 目录支持 + 已连通 + 操作类够 | 授权后即可用 |

这三者**不能互相顶替**。把"还没选"说成"产品不支持"，客户会以为我们能力不够；
把"还没选"说成"你还没连"，客户会去连一个他自己都没定的系统。所以界面上三种文案、
三个动作，状态面的汇总也分开计数。

## 怎么用

**包作者（模板仓 / 包清单）**

```json
{
  "key": "warehouse",
  "provider": "wms",
  "providerRole": true,
  "allowOperations": ["read", "write"],
  "optional": false
}
```

- `providerRole: true` 是显式开关：有它，`provider` 按**角色名**解释；没有它，语义和以前完全一样。
- 其余字段（`allowOperations` / `allowActions` / `optional` / `key`）语义不变。
- 角色名是全局键：同一个 `wms` 在两个包里必须指同一件事，客户不会答两次。

**客户（设置 → 连接 → 连接器卡片）**

1. 卡片上该行显示"待选系统"，右侧是一个下拉框。
2. 下拉里**只有自己已经连通的系统**，且只列能覆盖本包所需操作类的那些。
3. 选中 → 包立刻转"已接通（待授权）" → 点一次授权即完成。
4. 以后想换系统：同一行的下拉框改成"换系统"。

**售前话术**

- "这个模板不绑死某一家厂商：仓库系统你们自己在用哪个，就在卡片上选哪个。"
- "选完就通了，不需要我们改包。"
- "如果你们选的系统我们目录里的动作面不够（比如只能读不能写），卡片会直接说缺哪一类，
  不会假装能写。"
- "候选只列你们已经连上的系统——没账号的系统选了也接不通，所以我们不摊一本 1570 家的
  目录给客户做选型。"

## 平台不做的事（都是刻意的）

- **不预设默认厂商**。替客户猜一个，等于把"你有没有接通"从事实变成猜测。
- **不跨用户共享**。映射是 `(客户, 角色)` 一行，A 选了旺店通，B 第一次仍然是"待选系统"。
- **不回退备选**。一旦选定，解析只用这个系统；映射的系统覆盖不足就如实报缺口，
  绝不偷偷换用 `alternativeProviders`。
- **不提供全目录浏览选型**。候选 = 已连通 ∩ 覆盖所需操作类。
- **不在写入时校验目录存在性**。填了一个目录里没有的 id 不是 400，而是解析时报
  "未知 provider + 改选入口"——这是事实陈述，不是请求格式错误。

## 改选之后会发生什么

改选（或清除）映射会：

1. 重算**所有声明该角色的包**（跨包，不只当前这个）；
2. 旧系统名下的绑定令牌**作废**——它授权的对象已经不是客户选的那个系统了；
3. 该行回到"已接通（待授权）"，下一次写入会话配置时生效。

不会主动打断正在跑的会话（和 `stale` 的既有行为一致），但状态面会提示需要重新授权。

## 现状与边界

- 平台侧已就绪：声明校验、映射存储、解析、状态面、授权集合、HTTP 路由、界面。
- **供应链连接器包已声明角色**（2026-11-08，pack 1.1.0）：`wms-snapshot`、`supplier-portal`、
  `carrier-portal` 三条带 `providerRole: true`，市场按版本通道重发。三条仍为 `optional`
  ——optional 回答的是"这个包能否在没有它的情况下用"，与"能否被满足"是两件事，后者已由
  角色绑定解决。
- 夹具：`paas/test/fixtures/connector-bindings/supply-chain-after.json` 与真实包**逐字节一致**；
  早前那份从 `-after` 派生的 `supply-chain-role.json` 已退役——真包自己声明了角色之后，
  它是纯重复，留着只会与源分叉。
- 一个角色映射到**一个** provider。一对多 + 负载均衡是另一套语义，未做。
