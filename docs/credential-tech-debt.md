## 1. 两套凭据链并存 → 不做

```
旧链 credential-refs.js   12 个 ref，各带 markInvalid / renewOn401 / degraded（17 处）
新链 credential-resolve.js  三层级联，零失效恢复语义（0 处）
```

**缺口是真的**：新链服务 L1/L3/L4，但只有"读不到就当没有"；旧链有完整的
401→续期→降级链路。

**为什么不抽象**：现在没有任何调用方需要新链 + 失效恢复的组合。抽象它等于给不存在
的需求造接口，而抽象出来的形状会被第一个真实用例推翻。**等真有一个服务需要时再做**，
届时的形状一定和现在猜的不同。

## 2. ref 表数据驱动化 → 不做

实测新增一个第三方要改 **5 处**：注册表一行、独立模块（8-13 个导出）、db 表、
路由文件、前端面板。

**为什么这 5 处删不掉**：12 个 ref 的生命周期完全不同——

- 词元/ciyuan-account：**服务端**调上游 key API 铸 key
- wire-customer/lex：**浏览器** PKCE 换 LogTO ID token（含轮换 refresh token 的续期）
- connector/chatwoot：用户**粘贴** PAT
- facet-market/paper-trading：设备配对

把差异压进一张配置表，会把"不一样"写成"看起来一样"——这是本仓反复出现的
缺陷形态（"配了以为生效"）。**它的收益只是开发体验，代价是六条线的凭据链。**

## 3. L3/L4 无 UI → **已做** ✓

```
L1（个人 provider）：Models 页已做 ✓（含 /api/llm/upstreams 单源）
L3（MCP 端点覆盖）：后端 API 齐备，扩展页无入口 ✗
L4（工具级凭据）：后端 API 齐备，扩展页无入口 ✗
```

**这是台账里唯一真正该做的**：功能已经上产（sha-857c129），但用户只能调 API 才能用。
一个没人能用的功能等于没做。

**开工条件已备**：API 契约在归档 change 的 `tasks.md`「已落地的 API 契约」段。
**必须如实标注**：`supported:false` 的服务显示"不支持按工具配置"，不要给出会被
403 拒绝的表单。

## 4. `endpointOverridable` / `credentialScopes` 零采用 → 等触发

全仓 **0 处声明**，等于功能全关。

**这不是缺陷，是设计**：默认关闭是有意的——一旦某 server 声明端点可覆盖，
`reconcile_mcp_registry.py` 的守卫会立刻报红点名"必须先改判据"（旧等式
"登记地址 == 实际所连"对它的用户不再成立）。

**所以采用它的动作本身就是被守卫着的**，不需要额外的工作项。

## 6. 旧表明文存量 29 行 → 做（低优先）

生产实测：6 张旧凭据表共 **29 行 token 不是 `v1.` 信封**（仍是明文）。

**为什么现在不做**：全部落在测试 cell，无真实客户数据；新写入已加密，存量会随
覆盖写自然减少。

**为什么记着**：一旦有真实客户数据，这条优先级**跳到最前**。届时做一次性 backfill
（读→`decryptCredential` 兼容旧明文→`encryptCredentialSync` 重写），
`scripts/test-credential-at-rest.mjs` 已有 6 条判据可复用。
