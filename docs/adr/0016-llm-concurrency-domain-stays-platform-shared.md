# LLM 并发域保持平台共享：按预算治理，按租户拆分推迟到套餐层

2026-10-04 事故把这条链逼到台前：演示 cell 的子代理稳定死在运行中途，根因是全平台内部流量（web 聊天、bot 回复、定时任务、小程序）共用部署者的单一 sub2api 账号，sub2api 按账号并发准入直接拒绝（"Concurrency limit exceeded for user"，上游已知行为）；而 dsh 的 LLM 适配器按报错文案的措辞做正则分类，该文案既不含 "429" 也不含 "rate limit"，落入不可重试的兜底桶，运行时内置的重试机器（dsh-llm-retry，已在 bundle 中加载）于是正确地拒绝重试——回合死亡，UI 只显示裸失败。机器各层都按设计工作，设计没有闭环。

决策四条：①韧性契约是验收线：任何回合不因瞬时错误死亡。分类缺口在配置层补全（把兜底桶纳入 provider retryPolicy 的可重试集合，normal 模式有界退避），并向上游报真正的缺陷——分类应基于响应状态码与语义，而非文案正则。②并发域保持平台共享：本期不按租户拆 sub2api 账号。预算治理走「找到 sub2api 准入上限并按平台真实并发调定」；账号池（组）本就是为并发建的，准入上限拧开即释放真实并行度。③同 cell 内父回合与子代理自撞是产品形态的常态（并行委派是能力），因此客户端有界重试是永久底座，不是等上游修复的权宜。④失败与重试必须可见：子代理卡片显示真实终态原因，会话流消费重试事件——故障不允许只活在日志里。

## Considered Options

- 平台自有出口代理（把分类、重试、按用户排队收敛到自家新组件）：dsh 已内置整套重试机器且已在运行时里，缺的只是一个错误码没进集合；新增热路径组件（SSE 透传）是重复造轮子。否决。
- 压低 cell 内并行度（maxParallelToolCalls）减少自撞：并行子代理是产品能力，为迁就网关准入削足适履。否决。
- always 重试模式（无限重试直到成功）：限流风暴时变成长队，成本无上界。否决——normal 模式有界退避。
- 立即按租户拆 sub2api 账号：受 v0.2.x admin 无造键端点约束，要么逐账号 SSO 自开、要么面板 JWT 自动化，成本与收益不成比例；且拆域不消除同 cell 自撞，重试反正不可省。推迟到套餐层，届时每租户独立账号同时解决并发隔离与计费归属。

## Consequences

- 兜底桶盲试（每次失败最多 N 次有界重试）是接受的浪费；上游状态码分类落地后配置里的兜底码保留为无害冗余。
- 若探查证实 sub2api 准入上限是硬编码，平台在该顶内生存：重试吸收 + 后台流量（定时任务、bot）与交互流量错峰是仅有的缓冲，预算问题在租户增长后以更尖锐的形式回归——那是套餐层的启动信号。
- 上游若长期不修分类，跟随升级（ADR-0007 节奏）不改变本决策：配置层的可重试集合已闭环。
- 会话流显示重试进度后，任何网关侧降级（限流、5xx、抖动）首次对用户可见，排障不再依赖挖 session 日志。
