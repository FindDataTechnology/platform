# 定时任务并入统一任务引擎

cron-module 的规格（绑定角色+专属会话、排队、顺序执行、重启确定性）本来就是任务引擎规格的子集，而指挥层（委派）需要一个带生命周期与依赖的任务内核。决定：不为指挥层另造引擎，而是把 cron 泛化为统一任务引擎——定时任务是"带调度触发的任务"，cron 调度器成为它的定时前端（恰如聊天是它的委派前端），/tasks 成为唯一任务中心。代价是 cron-module 规格要迁移修订，但那是文档功；换来的是一个任务宇宙、一套 UI、一条执行通道（collector 模式已有 bot-relay 与 cron 双消费者验证）。

## Considered Options

- 两个引擎并存（cron 归 cron、委派另起）：被否——"任务"一词在产品里立刻分裂为两个概念，/tasks 两张脸，执行通道重复建设。
