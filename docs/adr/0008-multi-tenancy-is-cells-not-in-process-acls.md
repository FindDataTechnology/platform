# 多租户隔离是 cell（进程+数据根），不是进程内 ACL

fd-prod 从单进程迁往多用户时面临两条路线：给 documents/resources/文件路由加 owner 列做进程内虚拟层，或激活既有的 gateway+cell 拓扑（每登录身份一个服务进程、一个数据根、一个代理工作目录）。决定走 cell：文件面之上还有 agent 运行时——单 dsh 进程服务所有人的对话、上下文、cron 与委派，进程内 ACL 治不了这层共享，进程边界是唯一覆盖全部泄漏面的隔离原语。准入收口在身份提供方（Logto 注册/邀请），网关不设第二套名单——两处闸门必然漂移。Agent 服务（a2a）的可用性语义是「尽力常驻」：承载服务的 cell 同受 idle 回收，调用经网关按 owner 拉起恢复，不作 SLA 承诺。
