# 执行槽抽象：串行默认，有界工作槽旋钮

指挥层要同时支持串行（一个 cell 一次一个 turn，cron 语义原样）与并行（多角色同时开工）两种模式。决定：以"执行槽"统一两者——主槽恒在（交互对话 + 串行任务队列），工作槽按需 spawn、以单一角色终其一生、空闲回收、数量受上限旋钮控制（本机默认放开，fd-prod 置 0），同一内核、两种调度策略。反直觉但成立：并行比串行 fan-out 更温柔——工作槽零 preset 切换，而主槽串行换角色每步要付一次 bridge 重启。fd-prod 置 0 是资源决定（4GB 节点 OOM 前科），不是能力缺失；工作槽是"新鲜 home"专业户，spawn 必须走既有 dsh-profile 引导路径，不能另起一套。

## Considered Options

- 一步到位上多运行时常驻池：被否——fd-prod 内存预算不成立，且串行模式已能交付内核与委派两期的价值。
- 只做串行、并行留给跨 cell（MC 层）：被否——"一声令下、多角色同时开工"的演示画面是本程序首要验收，且 DshBridge 本就是可多实例的类。
