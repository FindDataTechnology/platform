# 詞元是 sub2api 的增量谱系 fork：月度跟上游 + 只增不改，与 registry 冻谱系成对

萬星·词元（模型/令牌线）需要 sub2api 不具备且上游 roadmap 零交集的能力：语音
（ASR+TTS）、rerank、serpapi 式搜索中转——本质是转售生意（池化上游 key、外部
调用者按量扣费），与 sub2api 拼车模型同型。决策四条：

①**形态 = 增量谱系 fork**（org 私有独立仓 `sub2api`，同 bmai 生态先例），不是
上游加薄网关：转售模型里 sub2api 的真正资产是 key/分组倍率/消费窗口/账本/面板/
充值整套机器，分层要全部 reimplement，fork 原生复用；计费面三 ADR
（0011/0014/0022）已把钱包定死在 sub2api，fork 是唯一保单钱包的深度定制形态。
②**tag 编码上游基线**（`ciyuan-vX.Y.Z-N`）：与 ADR-0017（registry 冻谱系、安全
单行道、功能永不并入）相反，本谱系**月度合并窗**常规跟上游 + **安全快车道**
（notes 见安全字样天级单独滚）；上游周均 2 版且安全修复藏于普通版本（0.2.14
默认管理员可爆破、EasyPay 回调伪造为实证），落后即安全风险。
③**只增不改纪律**：自有代码全在 `lanes/` 等新增包，上游文件仅触碰台账登记的
缝点集合（路由注册/账号枚举/计量钩子/前端导航/i18n）；fork-diff 台账样式对齐
registry-fork-patches。④**能上游则上游**：普适补丁（#6421 按 key 用量查询、
虚拟用量端点）以 cherry-pickable 独立提交回馈（签 CLA），合入即退役本地补丁。

降级预案前置：连续三个月度窗记录 merge 用时，单窗 >1 天触发显式降级决策
（冻谱系 ADR-0017 模式或车道外提独立服务），不允许无决策硬扛。LGPL-3.0 对
SaaS 运行零公开义务；若将来随私有化交付分发，薄车道架构使拆出仍是退路。

## Considered Options

- **sub2api 之上加薄网关（词元层）**：按「平台内部消费」优化过，但搜索是 serpapi
  式转售——分层被迫 reimplement key/窗口/账本机器，且双钱包违背「它管钱，不管
  生意」（ADR-0014）。否决，保留为降级路径之一（车道外提）。
- **冻谱系（ADR-0017 模式）直接套用**：registry 当时选冻结是因为「跟」太痛；词元
  需求恰恰是「定期跟上游」，冻结与诉求相反。否决为起点，保留为降级路径。
- **纯透传搜索（调用者直说 SerpAPI 协议）**：多上游无法归一、计量口径分裂。否决，
  改自有统一协议（engine 选择器 + 统一信封）。
- **等上游做语音/搜索/rerank**：上游方向纯 chat 订阅池（九版 release notes 零
  交集实证），商业模式不同型（订阅拼车 vs API-key 池化转售）。不可期。

## Consequences

- 首窗即从 v0.2.16 起 fork，顺手还清 0.2.7 落后 9 版+安全修复欠账；部署侧唯一
  变更是镜像 tag，key/余额零迁移。
- 团队首入 Go 谱系维护（栈为 Node/TS+Python）：车道是无状态 Go、月度 merge 机械，
  三月检查点是显式退出阀而非遥遥无期的坚持。
- 上游回馈线从零开始：需签 CLA；每合入一个普适补丁，fork diff 永久缩小一块。
- polish-fusion 挂账的「内置模型」归属随之落地：词元 = token.finddatatech.cloud
  产品名，其模型/API 目录即该条目来源（终态）。
- 壹座/萬星对三车道的消费集成（pack/runner/门面接线）是后续增量 change，本 ADR
  不含。
