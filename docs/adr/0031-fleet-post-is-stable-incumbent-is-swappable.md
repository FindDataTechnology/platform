# ADR-0031: 舰队的岗位是稳定实体，在岗者可换

日期: 2026-10-23
状态: 已接受（grill-with-docs 两轮裁决，2026-10-23）

## 背景

舰队（cell 内自治 agent 组织，见 CONTEXT.md 词条）要支撑「持续维护」：人员更替（换 persona）、节奏调整、暂停归档，且组织记忆（KPI 槽位、报数史、拍板归属）不能断。有两种建模：

- **薄覆盖层**：舰队成员=对既有运行时对象（persona/cluster/a2a）的直接引用，不引入新身份。实现最省，但换人即换引用，一切历史挂在 persona id 上，人员一换史就断。
- **岗位实体**：舰队的成员是稳定的「岗位」（Post），携带自己的身份、KPI 槽位声明、节奏规格与组织位置；「在岗者」（Incumbent）只是岗位上的一个可原子替换的引用。

## 决策

采用**岗位实体**：Member 行稳定存在，targetRef 可换防；换防后岗位标识、组织位置、槽位、报数史、拍板归属全部延续，物化任务与专属会话默认延续（可选清史重开）。配套规则：角色与动态集群全局唯一岗（报数归属无歧义），Agent 服务（a2a）可多岗（外部执行、无报数归属问题）。

## 后果

- 正面：组织记忆存活于人员更替之上——这是「公司式舰队」可长期运营的机制根基；报数/拍板/驾驶舱全部锚定岗位 id，下游三刀（report-lane/decision-lane/templates）不需要任何「身份迁移」逻辑。
- 负面：多一层间接（岗位→在岗者→对象），管理面必须处理悬空（待补岗）态；换防有会话语义选择（继承/清史）需要主人决策。
- 曾考虑的替代：薄覆盖层被否——省下的实现量会在第一次换人时以「史断」的形式连本带利还回来。
