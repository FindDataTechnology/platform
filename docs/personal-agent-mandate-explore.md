# 个人超级代理 / 幕僚团 explore（personal-agent-mandate）

> 2026-11-09 `/opsx:explore` 一轮。用户命题：「个人的超级代理 agent 或 agent 团队，可以代表人制定决策和回答问题」。
> 本文是**调研底稿**，不是需求单。立项按 §八 的 change 拆分走 OpenSpec。

---

## 一、结论先行

1. **不需要新建平台。** 零件已有 60–70% 且在产：cell（身体/车道）、preset 人设（岗位）、fleet（团队一等公民）、
   deputy 常务岗（服务端强制授权的 AI 裁决）、principal-facade（对外接待面）、永忆（L0→L1→L2）、ask card（反问你）。
2. **缺的是三层语义**，不是缺功能：
   - **授权层**：今天的委托策略只有「类别 → 谁裁」一维，无法表达「允许你在报价上自主，但不许你替我承诺交期」。
   - **判例层**：AI 只读得到「主人在拍板队列里的历史裁决」，读不到你在邮件/IM 里亲自回的那句话——而那才是口径主源。
   - **对外身份审计层**：它替你说的话没有一等账，无法审计、无法追认、无法撤回。这是对外代理的第一道坎，不是次要功能。
3. **顺次**：先 Lane A（事务拍板，deputy 扩域），后 Lane B（对外接待，披露闸 + 拟人身份）。理由见 §七。

## 二、用户四问定调（2026-11-09）

| 问题 | 裁定 | 对设计的影响 |
|---|---|---|
| 代表范围 | **四类全要**：对外答人 / 对内拍板 / 替我推进 / 替我学习产出 | 不是单一场景产品，必须有一个统一底座，四个消费面 |
| 权限上界 | **多模式，用户自选**：怎么决策、能做什么、知道什么范围 | 授权是三维矩阵，不是开关；且「知道范围」同时是披露边界 |

| 首发场景 | **2（阻塞与拍板）+ 3（对外接待与商务问询）** | 两条流水线共用底座，按 §八 拆三个 change |

## 四、核心新对象：委托状（Mandate）

### 4.1 三维

```
                        域 domain（可枚举，按业务面切）
        事务拍板 │ 对外沟通 │ 事项推进 │ 研究产出
  ┌──────────────┬──────────────────────────────────────────────┐
  │ mode         │ advise      只给判断，不动手                  │
  │ 决策模式      │ draft       起草好，你一键发                  │
  │              │ act-notify  先做，事后即时通报                 │
  │              │ act-silent  自主，仅进日报                     │
  ├──────────────┼──────────────────────────────────────────────┤
  │ action       │ read / draft / send / commit / spend / sign /  │
  │ 动作范围      │ schedule  + 额度上限 + 期限 + 撤销窗口          │
  ├──────────────┼──────────────────────────────────────────────┤
  │ knowledge    │ read_scope    ：能读哪些记忆层 / 语料          │
  │ 知情范围      │ disclose_scope：对外能说到第几层（金额/人事/   │
  │              │                 未公开计划/客户名）             │
  └──────────────┴──────────────────────────────────────────────┘
```

### 4.2 关键判断

- **read_scope 与 disclose_scope 必须是两个闸。** 让它读全部记忆 ≠ 允许它对外承认「下周要裁员」。
  披露闸落在**出站路径**（IM 发送、门面应答、邮件回信），与 deputy 的 403 同构：服务端校验，不靠提示词。
- **mode 是用户体验的核心旋钮。** 同一条「客户问报价」，可以先配 `draft`，攒够一致率再升 `act-notify`。
  mode 应支持**按域独立**与**按对象独立**（对老客户放宽、对公众收紧）。
- **额度与期限是一等字段**，不是备注。`spend ≤ N/月`、`commit ≤ 交期 ±X 天`、`有效期至 2026-12-31`、`撤销窗口 30 分钟`。
- **撤销窗口**：`act-notify` 的语义是「已发出但 X 分钟内可撤回」。对外消息这类动作，撤回窗口是它敢用 `act-notify` 的前提。

### 4.3 与既有 delegationPolicy / action-gate 的关系

**长在 `action-gate` 上，不另造一套闸。** `action-gate` 已提供动作注册表、五级风险、三级确认档位、单一执行路径与审计台账；
委托状只是它上面的一层**策略**：给定（域，动作，参数）返回「该不该做、以什么档位做、能说多少」，
由 `preflightAction`（`lib/action-preflight.js:186`）在既有前置检查之后调用，`executeRegisteredAction` 只消费结论。
披露校验也挂在同一个 preflight 上——因此不需要第二条出站路径，也就没有绕过口子。

**policy 结构是扩展，不替换。** `normalizeDelegationPolicy` 的 `routes/maxSeverity/dailyBudget` 保留原义，
新增 `domains[]`（每域一个三维块）。存量配置迁移为 `domains: [{domain:'ops', ...原值}]`，
未配置域一律回落 `advise` —— 即「今天的行为」是明天的下界，不会因为上新能力而放大权限。

**要重新审视的硬编码**：`config-change / 人事 / 花费` 三类「永不可委托」是为**舰队内部**定的。
到了个人事务域，「花钱」恰恰是最常见的委托对象（打车、订阅、采购）。
建议：保留「舰队内部拍板」的硬编码不动，个人事务域用**额度**替代**类别禁令**——不可委托的不是「花钱」，
而是「超过额度的花钱」。这条改写必须在 change 的 spec delta 里显式写清，不能默认继承。

## 五、个人幕僚团拓扑

```
            你
             │ 委托状（Mandate：四域 × 三维）
             ▼
      ┌─ 幕僚长 Chief of Staff ─┐   ← 唯一持有对外身份；分诊、路由、汇总
      │  所有出站消息从它发       │
      └──┬──────┬──────┬───────┘
         │      │      │
     领域专家   联络官   审计官      书记
   技术/法务/  对外口径  唱反调/否决  记账/判例
   商务/数据   身份切换   核对真实偏好  日报/回溯
```

**两处必须新造，且不能省：**

- **审计官（否决权）**：唯一职责是回答「这是主人的真实偏好，还是你在拿自己的推演当主人的偏好」。
  deputy 设计里已经有「判例源只取 owner 裁决」这条防污染纪律，但那是**禁止输入污染**，不是**主动唱反调**。
  个人代理的风险形态不同：它会在正确判例的基础上过度外推（「老板上次同意了 A，这次 B 类似」）。
  审计官的产出应当是结构化的：`同意 / 有异议但放行（留痕） / 阻断并上报`，三态都要落账。
- **幕僚长＝单一出站**：所有对外发言过一个角色。否则「以我名义说了什么」的账分散在 N 个 agent 里，无法审计。

**这条拓扑本身就是一个 fleet。** 不建议新造「个人团队」对象——`agent-fleet-core` 的岗位/节奏/报数/拍板/花销
全部可复用，缺的只是角色模板（`auditor` 岗位类型）与「幕僚长作为唯一出站」的运行时约束。

## 六、闭环六步，两处是缺的

```
授权状 → 检索判例 → 判断 → 执行/作答 → 记账 → 你的更正 ─┐
              ▲                                       │
              └──── 蒸馏为候选判例（人批生效）──────────┘
```

| 步 | 今天 | 缺 |
|---|---|---|
| 授权状 | 一维 policy | 三维 + 额度/期限/撤销窗 |
| 检索判例 | 只读拍板历史（限 owner） | 纳入「你亲自答复」的原话；纳入你改过的草稿 diff |
| 判断 | deputy 单岗 | 专家 + 审计官的两段式（先判、再被质疑） |
| 执行/作答 | 拍板走送达管线；对外走门面/IM | 出站披露闸；身份口径切换 |
| 记账 | 拍板有 resolved_by/evidence | 对外发言账（`spoken_by / mandate_ref / precedent_refs / disclose_level / reversible_until`） |
| 更正 | reopen 已有的裁决 | **更正 → 规则候选** 的蒸馏管道（接 `persona-self-evolution` 的「不直接生效」纪律） |

**判例污染的新形态**（要写进 spec）：
「代理起草 → 你原样发出」的答复，字面上是你的口径，实际上是代理的口径。若把它当判例回喂，会自我强化。
建议判例分级：`owner-authored`（你手打）、`owner-approved`（你原样发了代理的稿）、`deputy-ruled`（代理自裁）；
**只有前两级可作判例**，第三级只能作「行为一致性」统计。

## 七、两条首发流水线

| | **Lane A · 事务拍板** | **Lane B · 对外接待** |
|---|---|---|
| 起点 | deputy 常务岗（在产） | principal-facade（在产） |
| 要做 | policy 三维化；判例源扩到亲自答复；域从「舰队类别」扩到「个人事务域」；`auditor` 岗位模板 | `disclose_scope` + 出站强制闸；内部显式/外部拟人的身份切换；对外发言账；溯源回执 |
| 复用 | `fleets.js` 授权闸、`decision_items`、送达管线、记忆镜像、digest | facade pack、对话/嵌入/IM 车道、计费瀑布、委派 A2A |
| 新造 | Mandate 对象 + 设置面（三维可视化配置）+ 审计官 | 披露闸 + 出站记账 + 回执面 |
| 主要风险 | 代理误裁（可 reopen，可逆） | **对外口径错误不可逆**；披露越界后果 ≥ 误裁 |

**为什么先 A 后 B**：Lane A 的执行链、审计字段、服务端强制授权都已在产，是增量；
而 Lane B 一旦口径错了是对外的、不可逆的。先在 A 上攒出「它在 N 件事上判断与我一致」的证据与更正数据，
才有依据让它用你的口吻对外说话。**这个顺序不是保守，是让 B 有可用的判例库。**

## 九、Lane A 的三个起始域（默认建议，待用户确认）

覆盖当前手工拍板量约八成：

1. **各线在途阻塞与依赖** —— 跨仓、跨会话、每次都要重新判断的那些（今天已在 `harden-fleet-tool-face-and-queue` 的射程内）。
2. **供应商/合作方的答复口径** —— 报价、交期、能不能做；与 Lane B 的商务问询同源，先不对外发，只做「判断 + 起草」。
3. **内部人事与排期冲突** —— 谁做、什么时候做；对应 `agent-fleet-orchestration` 的编导边。

## 十、未决问题（进 change 设计期再答）

1. **披露粒度**：域级（「财务话题一律不说」）还是事实级（「营收数字可说到量级」）？事实级准确但维护成本高。
2. **溯源回执形态**：对外拟人时，事后可查（被动）还是每条都带可点开的声明（主动）？主动会破坏拟人体验。
3. **判例冲突谁赢**：新判例 vs 旧判例 vs 本次上下文。缺冲突仲裁，代理会在两个判例间反复。
4. **一团还是多团**：你同时跑多条线（wire/paas/萬星/法律/VAAS），是一个幕僚团分域，还是每线一团 + 一个幕僚长？
5. **打扰预算的度量**：一天容忍几次打断？按「被忽略的卡片数」自适应，还是你直接设上限？
6. **撤销窗口的默认值**：对外消息 10 分钟？付款 30 分钟？分类默认 vs 统一默认。
7. **审计官的异议是否阻塞**：仅留痕放行，还是必须你裁决？两者成本差一个数量级。
8. **计费归属**：个人幕僚团的回合走谁的钱（平台补贴 / 主人池 / 你自己的键）——`Settler` 语义要落到个人场景。
9. **代理写记忆的溯源**：它写进你记忆的事实必须标 `authored_by`，否则半年后你分不清哪条是自己想的。
10. **权限降级的传播**：你把某域从 `act-notify` 降回 `draft`，已发出的承诺怎么处理（只影响新动作，还是要求它主动撤回）？

## 十一、风险

- **拟人化对外不可逆**：一句话发出去就收不回。这是 Lane B 必须后置的唯一原因。
- **披露越界 > 误裁**：误裁可以 reopen，泄露的金额/人事/未公开计划不能。
- **判例污染**：代理起草的稿被你原样发出后，字面是你的口径——三级判例分级是硬需求，不是优化。
- **自我强化**：审计官若与专家共用同一上下文/模型，会一起走偏；它的输入必须包含**反例**（你推翻过的历史）。
- **成本失控**：幕僚团多岗位 × 巡逻节奏 = 乘法成本。`dailyBudget` 要从「裁决条数」扩到「回合/词元」。
- **权限放大**：新能力上线时默认值必须是「不放大」（未配置域回落 `advise`），否则等于一次性给全部权限。

---

## 十二、明确不做（v1）

- 不做通用个人助理 OS（日程全托管、邮件全代收）——先把「拍板 + 商务问询」两条跑通。
- 不做跨用户代理市场 / 代理代代理。
- 不做语音电话、不做对外主动外呼。
- 不新造「个人团队」实体——复用 fleet。
