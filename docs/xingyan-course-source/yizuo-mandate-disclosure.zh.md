## 学完你能做什么

配完四个业务域之后，三件事同时成立：

- 「委托状」分区里每个域都有自己的决策模式、每日条数上限与撤销窗口，未配置的域标注「只给建议」；
- 「事项接入」分区里每个来源都有自己的开关，关掉的来源不会把事项送进任何域；
- 「行为一致性」与「各披露层级的对外样本」两处有真实数字，你能对着它判断该不该把某个域从「起草」升到「先做后报」。

## 前置条件

| 项 | 要求 | 不满足时的现象 |
|---|---|---|
| 壹座 | 能打开设置 → 管理 → 「委托状」 | 侧栏没有「委托状」与「事项接入」两项 |
| 账号 | 部署者本人 | 分区能看但不能保存，保存返回 401 |
| 一个已启用的业务域 | 至少 `团队运营` 或 `对外沟通` 之一 | 四个域全部显示「只给建议」，无法升档 |

本文用「团队运营」与「对外沟通」两个域举例。换成「事项推进」或「研究产出」，步骤完全相同。

## 术语

本课程全文只用「本课程写法」一列。同一个概念只用一个名字，读者与检索工具都按关键词定位。

| 概念 | 本课程写法 |
|---|---|
| 决定代理在某个域能自主到哪一步的授权 | 委托状 |
| 四个可配置的业务范围 | 域 |
| 只看 / 起草 / 先做后报 / 自主 | 决策模式 |
| 能读到的信息层级集合 | 读取范围 |
| 能对外说出的信息层级集合 | 披露范围 |
| 负责裁决舰队内部拍板项的代理岗位 | 常务岗 |
| 哪类事项进入哪个域 | 事项接入 |

## 步骤

### 1. 先分清「谁裁决」与「能自主到哪一步」

「拍板委托」回答的是**谁**裁决舰队内部事项；「委托状」回答的是**代理能自主到哪一步**。两件事分开配置：前者只管路由与日预算，后者管模式、额度与信息范围。

**输入**：能打开设置面板。
**动作**：打开「设置 → 管理」，确认同时看到「拍板委托」与「委托状」两项。
**产出**：两个分区都在，且「委托状」排在「拍板委托」之后。

![拍板委托：这里配的是「谁裁决」——类别路由、严重度上限、每日裁决上限；它不管代理能自主到哪一步](media/yizuo-mandate-disclosure/03-delegation.png)

### 2. 给一个域选决策模式与额度

![委托状分区：四个域各一行；「团队运营」与「对外沟通」已配成「起草，待我放行」，额度与撤销窗口已填；「事项推进」仍是「只给建议」](media/yizuo-mandate-disclosure/01-mandate-domains.png)

四档模式的含义只有一条区别：**代理能不能不等你就动手**。

| 决策模式 | 代理会做什么 | 你什么时候会用到 |
|---|---|---|
| 只给建议 | 只输出判断，不产出可执行动作 | 新域默认值；还在观察期 |
| 起草，待我放行 | 产出可编辑草稿，你放行才发 | 想省力但还不放心 |
| 先做，事后通报 | 直接执行，事后即时通报并给撤销窗口 | 已经反复确认过口径 |
| 自主，仅进日报 | 直接执行，不打扰你 | 高频、低风险、可撤回 |

**输入**：第 1 步打开的设置面板。
**动作**：在「对外沟通」一行把「决策模式」选成「起草，待我放行」，「每日条数上限」填 `3`，「撤销窗口（分钟）」填 `10`，点底部「保存」。
**产出**：出现「已保存」；刷新页面后该域仍是新值。

额度只有两个方向：**用完自动收紧一档**，永远不会因为超额度而放宽。撤销窗口填 `0` 或不填，表示这条动作不可撤回——不可撤回的动作不会被自动执行。

### 3. 分开勾「读取范围」与「披露范围」

![单个域的完整一行：决策模式、每日条数上限、有效期、撤销窗口，下面是两个分开勾选的范围](media/yizuo-mandate-disclosure/05-scopes-one-domain.png)

这一步是整套配置里最容易被忽略的一处：**允许代理读到某条信息，不代表允许它对外说出这条信息**。两个集合各自判定。

**输入**：第 2 步配好的域。
**动作**：在「可读取的范围」勾上 `内部`；在「可对外说的范围」只保留 `公开`。
**产出**：两行勾选状态不同。此后代理能读内部材料，但起草对外内容时会引用内部信息的部分被拦下，并给出越界项。

### 4. 决定哪类事项进得来

![事项接入：三个来源各一行，开关决定进不进得来；右侧显示它会进入哪个域](media/yizuo-mandate-disclosure/02-matter-intake.png)

开关只决定**进不进得来**，不决定能自主到哪一步——后者仍由第 2 步的委托状决定。默认全关，所以升级不会让任何个人事务突然被代理接手。

**输入**：一个已配好的域。
**动作**：在「事项接入」里把「跨线阻塞与依赖」打开。
**产出**：该行开关变为开启状态；此后这类事项按 `团队运营` 域当前模式处理。

### 5. 看两个证据面再决定放量

![事项接入下方的证据面：每域一致率与可比样本、各披露层级的对外样本量，以及「缺哪一层不能开自动发送」](media/yizuo-mandate-disclosure/02-matter-intake.png)

放量不是凭感觉。两个数字要同时看：

| 数字 | 在哪 | 它回答什么 |
|---|---|---|
| 行为一致性 | 「事项接入」下方的「行为一致性」 | 代理的判断和你实际判断吻合多少 |
| 层级样本 | 同一分区的「各披露层级的对外样本」 | 某个披露层级你到底验证过几次 |

样本不足时，把模式设成「先做，事后通报」会被服务端拒绝，并返回缺的是哪一层。这是有意的：**只说对过内部话术，不足以支撑自动对外报价**。

### 6. 看一次真实的拦截结果

![裁决端点的真实返回：decision=draft，越界项为 finance（pattern）](media/yizuo-mandate-disclosure/04-verdict-blocked.png)

当一段准备发出的文字命中越界，返回里会点名层级与命中方式，而不是笼统的「被拦」。

| 命中方式 | 含义 |
|---|---|
| `provenance` | 引用了读取范围之外的记忆或判例 |
| `pattern` | 正文里出现了金额一类可识别的模式 |
| `term` | 正文里出现了配置过的敏感词 |

**输入**：一个已把「可对外说的范围」设为只含 `公开` 的域。
**动作**：让代理起草一段含报价金额的对外回复。
**产出**：动作回落为草稿，返回里含 `finance` 与 `pattern`。按越界项改掉那一段后重试即可通过。

## 没成功时

| 现象 | 原因 | 处置 |
|---|---|---|
| 「委托状」分区一直显示 `Loading…` | 数据面首次请求还没回来 | 等几秒；若超过 30 秒仍空，刷新页面。分区存在但一直空，才是故障 |
| 保存返回 400 且提到 unknown domain | 请求里的域名拼错 | 四个合法域名是 `ops`、`external-comms`、`advancement`、`research`，只能用这四个 |
| 想把某域设为「先做，事后通报」被拒绝 | 该域一致率不足或对应层级样本不够 | 先保持「起草」跑一段时间；看证据面缺哪一层 |
| 渠道撤不回消息 | 渠道声明不可撤回 | 该渠道最高只能到「起草」。撤不回的自动发送等于事后通知事故 |
| 事项开了开关却没有任何东西进来 | 对应域的模式仍是「只给建议」 | 开关只决定进不进得来，先按第 2 步把域升到「起草」 |

## 自检

三条都可以用「已知答案」验证：

1. 打开「委托状」，任一未配置的域应显示「只给建议」且额度为空——如果你看到额度有数字，说明它被配置过。
2. 打开「事项接入」，三个来源开关应显示你上次保存的状态；把「跨线阻塞与依赖」关掉再刷新，状态应保持关闭。
3. 用一段含金额的文字触发一次对外发言，返回应点名 `finance`；把金额删掉重试，应通过。

## 下一步

- 想让代理接手更多类型的事项：先把对应域升到「起草」，攒够一致率再谈自动。
- 想让代理替你对外说话：先看「各披露层级的对外样本」——每个层级要各自攒够样本，自动发送才被允许。
- 团队层面的分工与节奏，见「拍板委托」与团队驾驶舱；本文只管授权这一层。
