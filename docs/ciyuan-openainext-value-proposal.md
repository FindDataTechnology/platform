# 萬星·词元 × OpenAI-Next：技术方案说明（选型决策版）

> 面向对象：正在评估「直连 OpenAI-Next」还是「经由萬星·词元平台接入」的技术/业务决策者。
> 立场声明：本文由词元平台方整理，但所有能力声明均区分【生产实证】（有对账数字或真回合
> 证据）与【设计承诺】（已实现、按文档行为），并如实列出已知边界与「何时不必选我们」。
> 数据截至 2026-10-16，生产版本 ciyuan-v0.2.16-9。

---

## 0. 一页结论

- **OpenAI-Next 是一条优质的上游通道**：OpenAI 协议兼容、能力面宽（chat / embeddings /
  图像 / 语音 / Seedance 视频），官方 SDK 换 base_url + key 即用。生产连续运行近一个月，
  计费逐笔可对账。
- **萬星·词元是架在这条通道（及其他上游）之上的网关/平台层**：解决直连方案绕不开的四件
  事——**多账号高可用、统一 key 与统一账本、按组计费治理、能力缺口补齐**（rerank/搜索
  走车道接入，仍是一把 key）。
- **一句话**：直连 OpenAI-Next 拿到"一条好通道"；叠加词元拿到"一套可运营、可对账、可故障
  转移的 AI 接入体系"。两件事不冲突，词元的上游就是 OpenAI-Next。

## 1. 两层各自是什么

| 层 | 形态 | 职责 |
|---|---|---|
| **OpenAI-Next**（api.openai-next.com） | 聚合上游服务商 | 提供多家模型的 OpenAI 兼容端点：对话、向量、图像、语音（TTS/ASR）、Seedance 视频（`/seedance` 前缀通道） |
| **萬星·词元**（sub2api 增量谱系 fork） | AI 网关 + 运营平台 | 账号池调度与故障转移、统一鉴权与账本、分组价目与配额、审计与用量面板、协议车道（rerank / 搜索 / 音频） |

词元底座是开源项目 sub2api 的增量谱系 fork：只增不改（ADR-0024 纪律），上游月度合并窗 +
安全快车道，基线保持零补丁。当前生产 = 上游 v0.2.16 + fork 补丁级 9。

## 2. OpenAI-Next 直接用：优势与边界（客观）

**优势【生产实证】**

1. **协议零学习成本**：OpenAI 官方 SDK 直接换 `base_url` + `api_key` 即用；生产上对话/
   向量/图像账号均以该形态稳定运行。
2. **能力面宽**：一家覆盖 chat、embeddings、图像、语音（TTS qwen3-tts、ASR whisper-1）、
   Seedance 视频生成（seedance-1-0-pro / seedance-2-5 已实证出片 720p mp4）。
3. **计费可对账**：视频成本按上游 ratio 透明换算，实测 87300 tokens → $0.8075 分毫不差。
4. **通道稳定性**：生产账号一个月内 133 次请求 / 2.9M tokens 连续无事故。

**边界【实证在册，如实告知】**

- **没有 rerank**：重排能力需另找上游（我们走硅基流动）。
- **模型目录 ≠ 可用端点**：sora-2 / veo3 / kling 等在目录中列出但调用 404（无对应路径）；
  doubao-seedance-1-0-pro 曾出现上游 503。
- **路由在服务商侧**：一个 key 一套全局路由，无法按"这个 key 只准用视频"做账号级能力隔离，
  也无法做自有的多账号轮转/冷却。

## 3. 叠加萬星·词元后，多出什么

### 3.1 一把 key，全能力

三车道（重排 / 搜索 / 音频）与 chat **共用同一鉴权链与账本**：同一把 key、同一余额与消费
窗口、同一用量面板。【生产实证】调用方只需维护一个凭据和一个对账来源，而不是每类能力
各管一家 API、各管一份账单。

端点形状（均已上产）：

| 能力 | 端点 | 协议 | 计量 |
|---|---|---|---|
| 重排 | `/v1/rerank` | Cohere/Jina 式 | 按请求 |
| 搜索 | 统一信封（engine + q + num） | 自有统一协议 | 按次 |
| 语音转写 | `/v1/audio/transcriptions` | OpenAI 兼容 | 按小时 |
| 语音合成 | `/v1/audio/speech` | OpenAI 兼容 | 按百万字符 |
| 视频 | OpenAI 平台 + seedance 能力路由 | OpenAI 兼容 | 按 token（上游 ratio） |
| 图像 | OpenAI 兼容通道 | OpenAI 兼容 | 按分组价目 |

### 3.2 高可用：不是"一个 key 挂了等客服"

【生产实证】词元内置账号池调度：

- **全候选轮转**：单账号失败自动换下一候选，**分级冷却**（额度/鉴权类 12 小时、瞬态类
  60 秒；400/422 请求形状问题不换号），全池尽才返回 5xx。冷却状态落库持久，**跨重启有效**，
  管理台可见。
- **能力路由**：账号按 `openai_capabilities`（chat / embeddings / seedance…）声明能力，
  调度只按能力集筛候选——seedance 专用账号永远不会被错派去跑 chat（该调度投影机制
  经历过一次真实回归并被修复加固，修复已入册回归测试）。
- **BYOK（用户自带 key）**：请求级 `X-Serpapi-Key` 覆盖，用户 key 优先 → 失败按 key 哈希
  冷却并**自动回退平台池**，响应头 `x-search-source` 三态如实标注（user / pool / 回退）。
  自带 key 的用量照样入账归因（0 费 + 归因前缀）。

对客户的直接含义：上游单账号额度耗尽、密钥失效、瞬时故障，都不再是"你的服务 5xx"，
而是平台侧换号续跑。

### 3.3 计费治理：每一笔都对得上

【生产实证，全部为真实用量行对账】

| 能力 | 单价（分组可配） | 实证 |
|---|---|---|
| 搜索 | $0.02/次 | 用量行分毫不差 |
| 重排 | $0.004/次 | 分毫不差 |
| ASR | $0.15/小时 | 1 秒样本 $4.17e-05 对账 ✓ |
| TTS | $15/百万字符 | 5 字符样本对账 ✓ |
| Seedance 视频 | 上游 ratio × $2/MTok（fast $9.25/MTok） | 87300 tok → $0.8075 ✓ |

配套治理面：按分组定价与倍率、余额/消费窗口前置检查（耗尽拒付不触达上游）、错误回合
与空回合免单、账号/用户双侧计费归因、完整审计日志与用量面板。

### 3.4 错误面工程化

【生产实证】车道错误统一形状：调用方问题 400、上游故障 502、池空 503，全部携带 lane +
engine 标识，**不外泄上游细节、故障不计费**。直连上游时常见的"上游 4xx/5xx 直接透传给
终端用户"问题在这里被收口。

### 3.5 运营与合规面

- 管理台：账号管理（含车道平台建号 UI）、分组与白名单、价目配置、订阅、审计日志；
- 版本纪律：增量谱系 fork，上游合并窗制度化，安全修复可快车道出片（近期 9 个补丁级
  均在一日内完成"修复→测试→出片→滚产→验收"全链）；
- 部署形态：sub2api 开源底座，托管多租户或私有化部署均可（私有化时上游凭据归自己管）。

## 4. 客观边界：我们不承诺什么

如实列出，供决策权衡：

1. **rerank / 搜索依赖第三方上游额度**：rerank 走硅基流动、搜索走 SerpAPI，上游月额度或
   余额耗尽时该车道会降级（池内轮转+冷却可续，但池子全空就是 503）。扩容手段是加账号
   进池，分钟级生效。
2. **视频通道已验证范围 = Seedance 家族**：sora-2 / veo3 / kling 等模型上游无对应端点，
   不在承诺范围。
3. **上游侧故障我们只能缓解不能消除**：doubao-seedance-1-0-pro 上游 503 这类上游侧问题，
   词元做的是如实报错 + 不计费 + 换候选，而非凭空修复。
4. **延迟多一跳**：网关层有转发开销（含计费与审计）。对延迟极端敏感、调用量极小、只有
   一种能力诉求的场景，直连更简单。

## 5. 选型对照

| 决策问题 | 直连 OpenAI-Next | 萬星·词元托管 | 词元私有化 |
|---|---|---|---|
| 接入成本 | 最低（换 base_url） | 低（一把 key + 官方协议形状） | 中（自运维一套栈） |
| 多能力一把 key | ✗（rerank/搜索另找） | ✓ | ✓ |
| 账号级故障转移 | ✗ | ✓（分级冷却+跨重启） | ✓ |
| 按组计费/配额/审计 | ✗ | ✓（生产实证对账） | ✓ |
| 能力隔离（这个 key 只能视频） | ✗ | ✓（capabilities 路由） | ✓ |
| 上游凭据归属 | 自己 | 平台 | 自己 |
| 适合谁 | 单能力、量小、试水 | 多能力、要治理与对账的正式业务 | 数据主权要求高、有运维团队 |

**建议路径**：先用词元发一把试用 key 跑通 rerank/搜索/音频/视频各一条真请求（各车道
端点与示例见 `/lanes` 入口页），对账数字与本文档附录核对无误后再切生产流量。
