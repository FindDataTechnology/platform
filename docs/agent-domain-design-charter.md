# Agent 域设计宪章（design charter）

> 状态：2026-11-03 v1 定稿
> 来源：dsh-superagent-prototype 调研（[deepseek-ai/dsh-superagent-prototype](https://github.com/deepseek-ai/dsh-superagent-prototype)，2026-10-31 发布，MIT）× 壹座既有域合流
> 地位：**设计评审与立案的对照基准**。新概念先过 §5 拒绝清单；新需求先证明不能成为既有概念的属性；新立案先对照 §2 铁律。
> 姊妹文档：`fleet-orchestration-modes.md`（O1–O5 编排提案）、`CONTEXT.md`（全域词汇）、fleet-vocabulary-policy 归档件（用户面词汇终词）。

## 0. 为什么有这份宪章

「系统设计是壹座的核心能力」要成立，设计质量就不能靠人自觉，要靠**自我强制的门**维持。上游原型（superagent）证明这套门可行且便宜：

| 门 | 机制 | 成本 |
|---|---|---|
| 少概念 | 每个新需求先证明不能成为现有概念的属性；维护「拒绝概念表」 | 一张表 + 一次评审提问 |
| 单写者 | 每种状态一个 writer，其余只读或问它；命令祈使态、事实过去态 | 命名纪律 |
| 文档可测 | 测试断言：文档只能向后引用、全链接可解、无冲突标记 | 一个 spec 文件 |
| 模型面有预算 | 「模型读到的一切」（工具/提示词/输入）按角色设 size budget 写成测试 | 一个 spec 文件 |

壹座现状：前两道门部分遵守但未成文；后两道门缺失。本宪章成文前两道，§7 给后两道的工具化路径。

## 1. 域全景（合流后）

```
┌────────────────────────────────────────────────────────────────────────┐
│ 信号层 Signal        kind + instance（event 边 / webhook / cron / peer） │
│   已落地：event 边（bot:<id> 形式，agent-fleet-orchestration）           │
│   规则：读位置幂等；自身身份空间；入口即过滤；无命中零扰动                │
└─────────────┬──────────────────────────────────────────────────────────┘
              │ Trigger 触发（不可变 · 带 actor · 幂等收）
              ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 研判层 Intent        两层，职责不混：                                    │
│   gate 准入（代码·确定性）：强度 explicit/inferred · 准入表 · 名单        │
│   assessment 研判（模型·无状态）：只对 inferred 判 接/停/忽略            │
│   放量模式：off → observe（默认记录"本会接"）→ auto（须主人明示开启）      │
│   ★ 本宪章新增——见 add-turn-mandate-lane 立案                           │
└─────────────┬──────────────────────────────────────────────────────────┘
              │ accept ⇒ Mandate 授权（策略版本 + 强度 + 范围，不可变）
              ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 回合请求层 TurnRequest   已落地（agent-turn-contract，2026-10-23）：      │
│   { source, targetRef, brief, evidence, resultSink, depth, budget,     │
│     chain }  纯函数派生，覆盖既有全部触发路径                            │
│   ★ mandate/evidence 记账字段由授权层挂入，契约不改                      │
└─────────────┬──────────────────────────────────────────────────────────┘
              │ Dispatch 派工（task-engine + worker 池）
              ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 回合执行层 Turn        已落地：runExecutionTurn + 注入缝 + carrier +     │
│   attribution + parked 驻留 + O1 事件收口                               │
└─────────────┬──────────────────────────────────────────────────────────┘
              │ Report（O1 事件：status/errorKind 结构化）
              ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 交付层 Sink           已落地：报数上行 / 聚合回投 / decision 审批队列     │
│   （fleet-decision-lane：escalate→open→approved→delivered，≤5/回合）    │
│   规则：回执幂等 · 同工单同会话按序 · 丢弃留档带 reason code             │
└────────────────────────────────────────────────────────────────────────┘
```

**合流时的重要勘误**：调研初判「O2 turnRequest 未落地」不实——`add-turn-contract`（10-23 归档）已把 turnRequest 做成纯函数派生契约，`add-fleet-orchestration`（10-23）已落地六种边，`add-fleet-event-wake`（10-24）已实现事件唤醒。**真正的缺口是授权层**：现行 event 唤醒是「命中边即唤醒」（上限内一律建回合），没有发送者身份、没有强度、没有准入表、没有影子档、没有去向记账。本宪章的增量集中在这一层。

## 2. 八条铁律

| # | 铁律 | 治什么病（壹座实证） | 出处 |
|---|---|---|---|
| 1 | **授权与上下文分离**：订阅/注入只送上下文，权威只来自 mandate | parked-preset 归因事故（上下文路径悄悄携带权威语义）；旁路注入改行为类缺陷 | superagent 002 |
| 2 | **授权不可变**：只有 accept 创建、人停撤销、恢复前重校验失败吊销三种操作；策略改版通知受影响者而不撤销在途 | 常务岗三硬闸升格为统一公式；防止「改配置悄悄改在途行为的」假正常 | superagent 001/002 |
| 3 | **代码守门，模型研判**：准入/名单/工具检查是代码；模型只研判 inferred 候选；消息永远只是决策的输入，不能改规则 | 抗提示注入的结构性保证；tool_risk 闸同理 | superagent 002 |
| 4 | **状态单写者**：每种状态一个 writer；命令祈使态（stopTicket）、事实过去态（assignmentStarted） | 并行会话扫走他人代码、双写漂移类事故的工程面版 | superagent 007 |
| 5 | **每个触发有去向**：disposition 记录精确终局（admitted / filtered+reason / would-accept / cap-refused）+ 结构化 reason code（码+值），拒绝自由文本归因 | 事件唤醒 cap 拒绝已有 O1 留痕，升格为统一去向账 | superagent 001 |
| 6 | **已读≠认领**：消息被 step 认领不算读；已读 = 其后有 Report 或回合结束跟随 | 「换 pod 缝隙丢消息」挂账的判定式收编 | superagent 003 |
| 7 | **人优先槽位**：并发满时人的消息/状态查询永远有一个额外槽；新工单挤不掉在办工单的响应 | worker 池公平性；TASK_WORKER_MAX=0 时休眠不可见 | superagent 003 |
| 8 | **注意力经济**：每条消息/每个面板元素都是成本，收益须大于成本 | 量化锚：路由备注 ≤30 词、对外消息硬限 100 词、审批注入 ≤5 条/回合（fleet-decision-lane 已有） | superagent 000/005 |

## 3. 冲突裁决记录

| 冲突 | 上游做法 | 壹座现状 | 裁决 |
|---|---|---|---|
| 会话粒度 | 每 Ticket 新建 session+目录，用完即弃 | persona 常驻 parked 会话（preset 切换=重启 5-10s 逼出来的） | **规则归上游，粒度归壹座**：「工单定义自己的状态，不跟随执行者」恰好消解冲突——授权/状态挂 turnRequest 层，执行面继续复用 parked 会话 |
| 无审批执行 | worker 无审批直接跑命令 | 多租户不可能（carrier/tool_risk 闸、cell 隔离） | 壹座保持闸；mandate 的 scope 字段与 carrier 层对接，授权强度决定闸的松紧（后续线，不在首批） |
| 单仓 vs 多租户 | 单 state dir、单 SQLite、记录无限增长 | fleets.db/packs.db 既有版图；有界环经验（机器历史 200 条环） | 只取规则（单写者、事务内入队提交后执行）不取架构；其无清理增长是反面教材 |

## 4. 拒绝清单（先立再防）

| 拒绝项 | 理由 | 再提条件 |
|---|---|---|
| 通用消息总线/事件流平台 | source=event 只接已有信号源；边必须显式、有界、可审计 | 永不（除非出现 ≥3 个无法表达为边的信号形态） |
| 第二调度器/第二执行路径 | 所有回合仍走任务引擎 | 永不 |
| 跨信号源身份映射实体 | 身份是触发元数据；对应关系是提示词文本（identities skill 模式） | 出现需要结构化映射的产品需求（如跨端代办人） |
| 工单/回合请求状态跟随执行器 | 请求须可恢复、可重试、可换防 | 永不 |
| 把路由器做成常驻智能体 | 拓扑是舰队级声明，路由决策属于编排骨架 | 永不（壹座拓扑比上游星型宽） |
| depth > 1 多跳编排 | 成本与失败归属方案未立 | 出现明确的成本与失败归属方案 |
| 自动重试/自动降级（失败先可见再谈处置） | 假正常修复的前车之鉴 | 失败可见性全面落地后按线再议 |
| mandate 直接改闸的松紧 | 授权层与执行闸（carrier/tool_risk）先各自成立 | 授权层上产后按证据再对接 |

## 5. 概念映射

| 上游概念 | 壹座对应 | 状态 |
|---|---|---|
| Source（kind+instance） | event 边（bot: 形式）+ webhook + cron + peer | 已落地（event/webhook 有界）；kind 插件化后置 |

| Mandate | 无 | **缺口**（立案） |

## 6. 词汇裁定

- `turnRequest`、`mandate`、`disposition` 为**内部原语，不透出用户面**。用户面继续用终词：回合 / 定时运行 / 流转 / 派活 / 待人工（fleet-vocabulary-policy 与 CONTEXT.md 纪律）。
- 运维面（驾驶舱）如需展示授权，用「授权来源」与「强度」两个词；「准入表」「影子档」为运维文档词。
- 上游术语对照（内部文档用）：Trigger=触发、Eval=研判、Mandate=授权、Ticket=工单（仅内部）、Attention=待人工、Disposition=去向。

## 7. 质量门（免疫系统）

1. **拒绝概念表纪律**（本宪章 §4 即起点）：任何立案若引入新实体，评审第一问 =「为什么不能是既有概念的属性」；答案入 §4。
2. **单写者检查**：新增状态字段须在 design.md 指名唯一 writer；无 writer 的字段不许入库。
3. **文档门（工具化候选）**：编号文档只能向后引用 + 全链接可解 + 无冲突标记，做成一个测试脚本（上游 `docs.spec.ts` 的移植）。
4. **模型面预算门（工具化候选）**：按角色（主岗/执行岗/研判）给「模型读到的一切」设 size budget 测试；现有 A/B 活体度量（注入缝 283→6330 字符）固化为 CI 基线。
5. **面板三问原则**（驾驶舱评审单）：每个元素回答「需要我现在做什么吗 / 系统健康吗 / 这件工作的来龙去脉」之一，否则删除；健康态不占空间；计数必须等于它链接的列表长度。

## 8. 分期落地路线

```
已落地（2026-10）                缺口（本宪章增量）
─────────────────              ─────────────────
O1 失败一等事件 ✅              A. 授权记账层：mandate（强度/basis/策略戳）
O2 turnRequest  ✅                 + 入站去向账（disposition）——行为不变红线
六种编排边      ✅              B. 准入表 + observe 影子档（opt-in 扩面）
事件唤醒+cap    ✅              C. auto 档（主人明示 + 显式接受规则）+ 恢复重校验
审批队列        ✅              D. worker 池人优先槽位（cap 0 休眠不可见）
驾驶舱/假正常   ✅              E. 质量门工具化（§7.3/7.4 两个测试脚本）
```

- A+B+C 立案为 `add-turn-mandate-lane`；D 并入同案（worker-pool delta）；E 独立小案后置。
- 分期红线：A 验收 = 现行全部唤醒路径行为逐字节不变（纯记账）；B 默认 off（零扰动）；C 默认关。
- 事件唤醒的研判模型若引入，沿用判据车道纪律：503 且 <200ms 快失败先查模型名；禁自证（评审≠cell 默认产出）。
