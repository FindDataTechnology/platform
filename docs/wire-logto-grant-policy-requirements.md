## 三·五、查证结论回填（柏讯侧 2026-10-25 回填，§2.2 关闭）

**租户无配置问题、无额外吊销策略，§2.2 关闭。** 源码级定案（Logto 1.42.0 审计日志 + OIDC
模型库 + 部署版本源码，取证全程只读，全文见 fd-wire 闭环报告 §八）：

1. 审计日志 10-24 全天两 client 零 RevokeToken——不存在「吊销事件」，此前疑似的
   revoke-on-login / max-session 策略**不存在**。
2. 真机理：wire/lex console 是 SPA 公共客户端，refresh token 带 `expiresWithSession` +
   `sessionUid`，**绑定铸币时的浏览器会话**；每次刷新三重校验（铸币会话存活/会话主体未变/
   会话当前 grant 未换），任一破坏即 `invalid_grant`（DB 行都还活着，非删除）。
3. **14 天绝对租约**：SPA refresh token 自铸币起 14 天，rotation 不续命（源码注释
   "do not have infinite expiration through rotation"；壹座 14:24 链 16 轮 rotation 后
   exp 仍钉在铸币+14d 数据互证）。租户无 TTL 旋钮（配置为空=全默认）。
   **现网四链 11-07 22:25-22:58 集体到点，与刷新频率无关。**
4. 壹座侧定案修正：「新授权杀旧链」仅在**同铸币会话**上成立（独立会话的新授权不杀链，
   23:57:36 重铸后 22:58 链次日凌晨仍成功 rotation=反例实锤）；裸登录不杀链（维持）。
5. 附带更正：壹座 23:21「瞬态 invalid_grant」实为**诊断脚本把 lex 的 rotator 刷到 wire
   端点**（client mismatch，张冠李戴），链无恙——生产 rotator 的 per-line 配对经复核正确，
   已补账号×线×client 配对单测钉死该类。
6. 运营纪律修正版（比原版更宽松）：人工登录/退出不受限（独立会话不碰链，双重实证）；**禁止
   的是**：①重跑复用旧会话 cookie 的铸币/登录脚本（同会话再授权换 grant=杀链）；②在铸币
   会话环境里登出或换账号。所有铸币统一走 platform mint 回调通道（审计可见），勿在 Logto
   宿主跑裸脚本（双向纪律，贵侧 10-24 三批宿主直打铸币亦属此类）。
7. 结构性方案修正（§2.3）：服务账号只解决人机共享互踩，**不解决 14 天墙**。5.x 决策口径=
   「每 cell 一个服务账号 + <14 天周期自动重铸（壹座 headless 铸币配方已具备）」；备选=
   舰队场景改机密客户端（Traditional Web，rotation 可续命），session 绑定语义未验证、动静大，
   不作首选。

## 四、非目标与边界

- 壹座侧不改代码（机制面已实证；策略/纪律落定后零改动全通）；
- 不拉长 ID token TTL（维持 1h）；不做跨用户凭据共享、平台级超级 token；
- 瞬态 `invalid_grant`（如 23:22 一次，15 分钟后同 rotator 自愈）按瞬态处理：行不 stale、下个
  tick 重试——已实证自愈，不构成本档事项。
